CLAUDE.md(전역 지침서)와 AI 에이전트 프롬프트의 차이

Claude Code를 쓰다 보면 자주 헷갈리는 두 개념, "CLAUDE.md"와 "서브에이전트(subagent) 프롬프트/시스템 프롬프트(system prompt)"를 나란히 비교합니다.

대상 제품Claude Code
전제 지식Claude Code 초급 트랙 수준
기준 버전공식 문서 원문 기준 (버전 미지정 시 최신 안정 버전)
확인 기준일2026-09-03
결론: CLAUDE.md는 "매 세션 시작 시 대화 안으로 주입되는 프로젝트 문서"이고, AI 에이전트(서브에이전트) 프롬프트는 "그 서브에이전트 전용으로 새로 구성되는 시스템 프롬프트(system prompt)"입니다. CLAUDE.md는 시스템 프롬프트 자체가 아니라 시스템 프롬프트 다음에 오는 사용자 메시지로 대화에 삽입되는 반면, 서브에이전트 프롬프트는 Claude Code 기본 시스템 프롬프트를 대체하는 그 서브에이전트만의 시스템 프롬프트입니다. 또한 서브에이전트는 메인 대화의 CLAUDE.md 계층을 그대로 물려받지만(Explore·Plan 서브에이전트는 예외), 메인 대화 기록이나 자동 메모리(auto memory)는 물려받지 않습니다. (출처: code.claude.com/docs/en/memory, code.claude.com/docs/en/sub-agents, code.claude.com/docs/en/agent-sdk/modifying-system-prompts, 2026-09-03 확인)

1. 핵심 정의

CLAUDE.md (전역 지침서)

  • 사용자가 직접 작성하는 마크다운 파일
  • 매 세션 시작 시 자동으로 읽혀 대화(conversation) 안에 컨텍스트로 주입됨 — 시스템 프롬프트 자체는 아님
  • 범위(scope)에 따라 여러 위치에 존재: 관리형 정책 / 사용자(user) / 프로젝트(project) / 로컬(local)
  • 같은 계층 구조가 메인 대화와 (Explore·Plan을 제외한) 서브에이전트에 동일하게 로드됨

AI 에이전트(서브에이전트) 프롬프트

  • 서브에이전트 정의 파일(.claude/agents/*.md 등)의 마크다운 본문 = 그 에이전트의 시스템 프롬프트(system prompt)
  • Claude Code 기본 시스템 프롬프트를 이어받지 않고, 해당 에이전트 고유의 프롬프트 + 환경 정보로 새로 구성됨
  • 서브에이전트마다 독립된 컨텍스트 창(context window)에서 실행
  • 메인 대화 기록·출력 스타일(output style)·자동 메모리는 기본적으로 물려받지 않음(포크(fork)형 서브에이전트는 예외)
용어 주의 "시스템 프롬프트(system prompt)"라는 용어 자체는 원래 Claude Agent SDK/API 레벨의 개념입니다. Claude Code CLI를 쓰는 사용자 입장에서 "AI 에이전트 프롬프트"라고 부르는 대상은 대부분 서브에이전트(subagent) 정의 파일의 마크다운 본문을 가리키며, 이 문서에서도 그 의미로 사용합니다. SDK를 직접 다뤄 시스템 프롬프트 자체를 코드로 조립하는 경우(§4)는 별도로 구분해 다룹니다.

2. 한눈에 비교

CLAUDE.md와 서브에이전트 프롬프트의 항목별 비교 (출처: code.claude.com/docs/en/memory, code.claude.com/docs/en/sub-agents, 2026-09-03 확인)
항목 CLAUDE.md 서브에이전트(AI 에이전트) 프롬프트
누가 작성 사용자(개발자·팀·조직) 사용자가 .claude/agents/ 등에 마크다운으로 작성, 또는 Claude Code 내장 에이전트는 사전 정의됨
담기는 위치 시스템 프롬프트 뒤에 오는 사용자 메시지로 대화(conversation)에 주입 해당 서브에이전트의 시스템 프롬프트 그 자체가 됨(+ Claude Code가 덧붙이는 환경 정보)
적용 범위 프로젝트, 사용자, 조직 단위로 계층화. 여러 파일이 이어붙여져(concatenate) 함께 로드됨 에이전트 1개당 프롬프트 1개. 다른 서브에이전트와 공유되지 않음
메인 대화와의 관계 메인 대화가 직접 읽고, 서브에이전트도 동일 계층을 물려받음(Explore·Plan 제외) 메인 대화의 시스템 프롬프트를 물려받지 않음. 별도의 독립된 프롬프트로 새로 시작(포크형 제외)
주 용도 코딩 표준, 워크플로, 프로젝트 아키텍처 등 "항상 참고해야 할 사실과 규칙" 특정 작업(코드 리뷰, DB 조회 등)에 특화된 역할·행동 방식·도구 권한 정의
도구 접근 권한 권한 개념 없음(내용 자체가 도구를 제어하지 않음) tools/disallowedTools frontmatter로 화이트리스트·블랙리스트 지정 가능
강제력 컨텍스트일 뿐 강제 설정이 아님. 반드시 지켜야 하는 규칙은 훅(Hooks)으로 별도 구현 필요 시스템 프롬프트 수준의 강한 지시이지만, 이 역시 도구 사용을 강제로 차단하지는 않음(차단은 훅으로)
파일 위치 예시 ./CLAUDE.md, ~/.claude/CLAUDE.md, ./CLAUDE.local.md 등 .claude/agents/*.md, ~/.claude/agents/*.md, 관리형 설정, --agents CLI 플래그(JSON)
호출 방식 세션 시작 시 자동 로드(하위 디렉터리 파일은 해당 디렉터리 파일을 읽을 때 온디맨드 로드) Claude의 자동 위임(설명 매칭), @에이전트명 멘션, 또는 Agent 도구 호출로 실행

3. 왜 이 둘이 자주 헷갈리는가

두 개념 모두 "Claude에게 무엇을 하라고 미리 일러두는 텍스트"라는 점에서 비슷해 보입니다. 하지만 결정적인 차이는 어디에 얹히는가입니다. CLAUDE.md는 이미 정해진 시스템 프롬프트 위에 "참고 문서 한 장을 끼워 넣는" 방식이고, 서브에이전트 프롬프트는 "시스템 프롬프트 자체를 새로 정의하는" 방식입니다. 공식 문서는 이 차이를 다음과 같이 명시합니다.

공식 문서 원문 근거 "CLAUDE.md content is delivered as a user message after the system prompt, not as part of the system prompt itself." — CLAUDE.md는 시스템 프롬프트 뒤에 오는 사용자 메시지로 전달되며, 시스템 프롬프트의 일부가 아님. (출처: code.claude.com/docs/en/memory, 2026-09-03 확인)
공식 문서 원문 근거 "System prompt: the agent's own prompt plus environment details that Claude Code appends, not the Claude Code system prompt." — 서브에이전트의 시스템 프롬프트는 그 에이전트 고유의 프롬프트와 Claude Code가 덧붙이는 환경 정보로 구성되며, Claude Code 기본 시스템 프롬프트가 아님. (출처: code.claude.com/docs/en/sub-agents, 2026-09-03 확인)

메인 대화 vs 서브에이전트, 시작 시 로드되는 내용 비교

1
메인 대화 — Claude Code 기본 시스템 프롬프트 + CLAUDE.md 전체 계층(관리형→사용자→프로젝트→로컬) + 대화 기록 + 자동 메모리(auto memory)
2
일반 서브에이전트 — 에이전트 자체 시스템 프롬프트(마크다운 본문) + Claude가 작성한 위임 메시지 + 메인 대화와 동일한 CLAUDE.md 계층 + Git 상태 스냅샷. 대화 기록·출력 스타일·자동 메모리는 미포함
3
Explore·Plan 서브에이전트(예외) — 위 2번과 같지만 CLAUDE.md와 Git 상태를 건너뜀. 대신 메인 대화가 이 서브에이전트의 결과물을 읽을 때 메인 대화 쪽 CLAUDE.md 컨텍스트가 이미 적용되어 있음
4
포크(fork) 서브에이전트(/subtask) — 예외적으로 메인 대화 전체(시스템 프롬프트·도구·모델·메시지 기록)를 그대로 상속

(출처: code.claude.com/docs/en/sub-agents "What loads at startup" 섹션, 2026-09-03 확인)

실무 영향 CLAUDE.md에 "vendor/ 디렉터리는 무시하라" 같은 규칙을 써 두어도, Explore·Plan 서브에이전트는 CLAUDE.md 자체를 건너뛰므로 이 규칙이 자동으로 전달되지 않습니다. 이런 규칙이 반드시 서브에이전트에 전달돼야 한다면, 위임 프롬프트에 다시 명시해야 합니다. (출처: code.claude.com/docs/en/sub-agents, 2026-09-03 확인)

4. 파일·코드 형태 비교

CLAUDE.md — 프로젝트 루트에 두는 마크다운

./CLAUDE.md

# 프로젝트 개요
이 저장소는 Node.js 기반 백엔드 API 서버입니다.

## 빌드·테스트 명령
- 테스트: `npm test`
- 린트: `npm run lint`

## 코딩 규칙
- 들여쓰기는 2칸을 사용한다.
- API 핸들러는 `src/api/handlers/`에 위치한다.
- 커밋 전 반드시 `npm test`를 실행한다.

이 내용은 세션이 시작될 때 자동으로 읽혀 대화 컨텍스트에 포함됩니다. 시스템 프롬프트를 바꾸는 것이 아니라, "이 프로젝트에 대해 알아둬야 할 사실"을 매번 다시 알려주는 방식입니다.

서브에이전트 프롬프트 — .claude/agents/에 두는 마크다운(frontmatter 포함)

.claude/agents/code-reviewer.md

---
name: code-reviewer
description: Reviews code for quality and best practices. Use after writing or modifying code.
tools: Read, Glob, Grep
model: sonnet
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.

frontmatter의 name·description은 필수이며, description은 Claude가 언제 이 서브에이전트에 작업을 자동으로 위임할지 판단하는 기준이 됩니다. tools로 도구 접근 범위를 제한할 수 있고, 마크다운 본문 전체가 이 서브에이전트의 시스템 프롬프트가 됩니다. (출처: code.claude.com/docs/en/sub-agents, 2026-09-03 확인)

참고: SDK 레벨의 "진짜" 시스템 프롬프트 조립

Claude Agent SDK를 직접 사용하는 경우(예: 자체 에이전트 제품을 만들 때)에는 시스템 프롬프트를 다음 세 가지 방식 중 하나로 명시적으로 지정합니다. 이때도 CLAUDE.md는 시스템 프롬프트를 바꾸지 않고, SDK가 대화 안에 별도로 주입한다는 점은 동일합니다. (출처: code.claude.com/docs/en/agent-sdk/modifying-system-prompts, 2026-09-03 확인)

  • 최소 기본값: systemPrompt를 지정하지 않으면 도구 호출만 지원하는 최소 프롬프트가 사용됨(Claude Code CLI의 claude -p와는 다름)
  • claude_code 프리셋: Claude Code CLI가 실제로 쓰는 시스템 프롬프트. append로 자체 지시를 뒤에 덧붙일 수 있음
  • 커스텀 문자열: 완전히 직접 작성한 프롬프트로 전체를 대체
시스템 프롬프트 커스터마이즈 4가지 방식 비교 (출처: code.claude.com/docs/en/agent-sdk/modifying-system-prompts, 2026-09-03 확인)
항목 CLAUDE.md 출력 스타일(Output Styles) append 방식 커스텀 systemPrompt
지속성 프로젝트별 파일로 영구 저장 파일로 저장, 재사용 가능 세션 한정 세션 한정
기본 도구·안전 지침 유지됨 유지됨 유지됨 포함하지 않는 한 사라짐
커스터마이즈 수준 추가만 가능 기본값 대체 또는 확장 추가만 가능 완전한 통제

5. 실무 판단 기준

이 규칙을 CLAUDE.md에 넣을까, 서브에이전트 프롬프트에 넣을까?

모든 작업·모든 대화에서 항상 참이어야 하는 사실(빌드 명령, 코딩 컨벤션, 프로젝트 구조)이라면 CLAUDE.md에 둡니다. 특정 역할(코드 리뷰만, DB 조회만 등)에서만 필요한 행동 지침이나 도구 제한이라면 서브에이전트 프롬프트에 둡니다.

CLAUDE.md에 적은 규칙이 서브에이전트에도 자동으로 전달되나?

일반 서브에이전트는 예. 메인 대화와 동일한 CLAUDE.md 계층을 그대로 로드합니다. 다만 Explore·Plan 서브에이전트는 예외적으로 CLAUDE.md를 건너뜁니다.

서브에이전트가 메인 대화에서 있었던 이전 대화 내용을 알 수 있나?

기본적으로는 모릅니다. 서브에이전트는 매번 새 컨텍스트 창에서 시작하며, Claude가 작성한 위임 메시지(작업 요약)만 받습니다. 예외는 /subtask로 시작하는 포크(fork) 서브에이전트로, 이 경우 메인 대화 전체를 상속합니다.

둘 다 강제 규칙(반드시 지켜야 하는 규칙)으로 쓸 수 있나?

아니요. CLAUDE.md와 서브에이전트 프롬프트 모두 "Claude가 참고하는 컨텍스트"이지 강제 설정이 아닙니다. 도구 사용 자체를 반드시 차단해야 한다면 훅(Hooks)의 PreToolUse 같은 기능을 사용해야 합니다. (출처: code.claude.com/docs/en/memory, 2026-09-03 확인)

문서 성격: 이 문서는 커리큘럼 코스 모듈이 아닌 별도 참고 자료입니다. 프로젝트의 index.html 모듈 목록에는 포함되지 않으며, Claude Code 중급(custom)·상급(advanced) 트랙 모듈 작성 시 배경 지식으로 링크해 사용할 수 있습니다.
