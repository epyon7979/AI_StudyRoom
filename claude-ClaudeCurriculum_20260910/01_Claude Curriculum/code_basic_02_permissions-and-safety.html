권한 모드와 안전장치

Claude가 언제 물어보고 언제 그냥 실행하는지 정하는 권한 모드를 익히고, 파일을 건드리지 않는 Plan 모드로 변경 계획만 받아 봅니다. 이 모듈에서도 파일은 수정하지 않습니다.

2. 학습 목표

설명

이 모듈을 마치면 다음을 할 수 있습니다.

  1. 현재 세션의 권한 모드를 상태 표시줄에서 확인하고 Shift+Tab으로 전환할 수 있다.
  2. Plan 모드로 파일을 수정하지 않고 변경 계획만 받을 수 있다.
  3. 작업 전에 git 복구 지점을 만들고, 세션에서 하지 말아야 할 일을 말로 지정할 수 있다.

3. 사전 준비

설명

3-1. 준비물

항목내용
필요 플랜Pro 이상. 시작 모드는 플랜에 따라 다릅니다(4-3).
설치모듈 01에서 완료. 추가 설치 없음.
사전 지식모듈 01 수료 — 세션 시작·종료, 셸 명령과 세션 커맨드 구분.

예상 사용량프롬프트 2회. Plan 모드는 파일을 읽고 탐색하므로 단순 질문보다 조금 더 씁니다.

3-2. 이 문서의 표기 방식

모듈 01과 같습니다. 커맨드·플래그·상태 표시줄 문구는 영문 원문 그대로 싣고 설명만 한국어로 씁니다. 상태 표시줄 문구(예: ⏸ plan mode on)는 화면에 그대로 나타나는 문자열입니다.

3-3. 이 모듈도 파일을 수정하지 않습니다

계획까지만, 실행은 다음 모듈에서

이 모듈의 실습은 Plan 모드에서 계획을 받고 승인하지 않는 데서 끝납니다. 계획을 승인하면 그 순간 파일 수정이 시작되기 때문입니다. 실제 코드 변경과 커밋은 모듈 03에서 다룹니다. 마지막 단계에서 git status로 파일이 그대로인지 확인합니다.

4. 핵심 개념

설명

4-1. 결론부터

권한 모드는 "Claude가 행동하기 전에 나에게 물어보는가"를 정하는 설정입니다. 모듈 01의 첫 세션에서는 변경마다 물었지만, 그건 설치 직후 첫 세션이라서 그랬습니다. 두 번째 세션부터는 플랜에 따라 묻지 않고 실행하는 모드가 기본일 수 있습니다. 그래서 무엇을 맡기기 전에 지금 어떤 모드인지 확인하는 습관이 먼저입니다.

4-2. 초급에서 다루는 모드 3가지

Claude Code에는 권한 모드가 여섯 가지 있습니다. 그중 초급에서는 아래 세 가지만 다룹니다.

모드묻지 않고 실행하는 것적합한 상황
Manual
설정값 default		읽기만모든 동작을 직접 검토할 때, 민감한 작업
Plan읽기, 그리고 auto 모드를 쓸 수 있을 때는 분류기가 승인한 명령바꾸기 전에 코드베이스를 탐색할 때
Auto전부. 대신 백그라운드 안전 검사가 붙음긴 작업, 승인 피로를 줄이고 싶을 때

네 번째 모드인 acceptEdits(파일 편집을 자동 승인)는 Shift+Tab 순환에 함께 나타나므로 이름만 알아 두세요. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

초급에서 다루지 않는 두 모드

dontAsk와 bypassPermissions는 이 커리큘럼의 초급 트랙에서 다루지 않습니다. 특히 bypassPermissions(--dangerously-skip-permissions 플래그와 동일)는 권한 확인과 안전 검사를 모두 끄는 모드로, 공식 문서가 컨테이너·VM 같은 격리 환경에서만 쓰라고 경고합니다. 일반 개발 환경에서는 쓰지 마세요. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

4-3. 내 세션은 어떤 모드로 시작하는가

플래그나 설정 파일로 지정하지 않았다면 아래 기본값이 적용됩니다. 위에서부터 먼저 맞는 줄이 적용됩니다. 공식 문서의 판정 순서 중 터미널·VS Code 확장에서 자주 만나는 경우만 추렸습니다. claude -p 실행이나 Bedrock 등 클라우드 제공자를 쓰는 경우는 순서가 더 있습니다.

상황시작 모드
관리자가 disableAutoMode를 꺼 둔 경우Manual
설치 또는 업그레이드 직후 첫 세션Manual
Pro·Max·Team 플랜, 터미널 또는 VS Code 확장Auto
Enterprise 플랜 또는 Claude Console API 키Manual

순서가 실제로 중요합니다. 예를 들어 Pro·Max·Team 플랜이라도 조직 관리자가 disableAutoMode를 꺼 두었다면(맨 윗줄이 먼저 맞으므로) Auto가 아니라 Manual로 시작합니다. 모듈 01에서 "변경마다 물어본다"고 했던 것은 "설치 또는 업그레이드 직후 첫 세션" 줄에 해당했기 때문입니다. 이번 모듈의 세션은 첫 세션이 아니므로, 관리자가 auto 모드를 막아 두지 않은 Pro·Max·Team이라면 Auto로 시작할 가능성이 높습니다. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

상태 표시줄에서 바로 확인할 수 있습니다

현재 모드는 상태 표시줄에 이렇게 나타납니다. ⏸ manual mode on(회색), ⏵⏵ accept edits on, ⏸ plan mode on, ⏵⏵ auto mode on. ⏸ 기호는 멈춰서 묻는 모드, ⏵⏵ 기호는 그냥 진행하는 모드라고 기억하면 편합니다. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

4-4. Auto 모드가 막는 것과 허용하는 것

Auto 모드에서는 별도의 분류기 모델이 각 동작을 검토해, 요청 범위를 넘어서거나 낯선 인프라를 건드리거나 적대적 콘텐츠에 의해 유도된 것으로 보이는 동작을 차단합니다. 초급에서 알아 둘 만한 항목만 추리면 이렇습니다.

기본 차단기본 허용
  • curl | bash 같은 코드 내려받아 실행
  • force push
  • git reset --hard, git checkout -- ., git clean -fd 등 커밋하지 않은 작업을 버리는 명령
  • 세션 전부터 있던 파일을 되돌릴 수 없게 파괴
  • 운영 배포와 마이그레이션
  • 작업 디렉터리 안의 로컬 파일 작업
  • lock 파일·매니페스트에 선언된 의존성 설치
  • 읽기 전용 HTTP 요청
  • 지금 작업 중인 저장소의 브랜치에 push
공식 문서의 경고를 그대로 옮깁니다

Auto 모드는 승인 요청을 줄여 줄 뿐 안전을 보장하지 않습니다. 방향을 신뢰할 수 있는 작업에 쓰고, 민감한 작업에 대한 검토를 대체하는 수단으로 쓰지 마세요. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

4-5. 안전장치는 세 겹입니다

겹누가 거는가내용
① git 복구 지점내가 직접작업 시작 전 커밋해 두면 무엇이 바뀌어도 되돌릴 수 있습니다. 가장 확실한 수단입니다.
② 대화로 선언한 경계내가 말로"push하지 마세요", "검토 전까지 배포하지 마세요"처럼 말하면 분류기가 그에 맞는 동작을 차단합니다. 기본 규칙상 허용되는 동작이라도 막힙니다.
③ 보호 경로·치명 경로제품이 자동으로.git, .claude, .vscode 같은 경로 쓰기와, 홈 디렉터리·작업 디렉터리를 지우는 rm은 어떤 허용 규칙으로도 자동 승인되지 않습니다.
②는 대화가 길어지면 사라질 수 있습니다

말로 선언한 경계는 규칙으로 저장되지 않고 대화 기록에서 매번 다시 읽힙니다. 대화가 길어져 컨텍스트가 압축되면 그 문장이 사라질 수 있습니다. 긴 세션에서는 중간에 다시 선언하세요. 확실한 보장이 필요하면 설정 파일의 deny 규칙을 써야 하며, 이는 중급에서 다룹니다. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

참고로 Claude Code는 커밋하지 않은 작업을 버릴 수 있는 명령(git reset --hard, rm -rf 등) 앞에서 스스로 git status를 실행해 작업 중인 변경이 있는지 분류기에 알려 줍니다. ①을 지켜 두면 이 검사도 함께 작동합니다. (출처: code.claude.com/docs/en/permission-modes, 2026-08-26 확인)

  4. Shift+Tab으로 모드를 순환해 봅니다

    Shift+Tab을 여러 번 누르며 상태 표시줄 문구가 바뀌는 것을 관찰합니다. Auto에서 시작했다면 첫 번째 누름은 Manual로 가고, 이후 default → acceptEdits → plan → 다시 default 순서로 돕니다. 아직 아무 작업도 시키지 않았으므로 어느 모드로 옮겨도 안전합니다.

  5. Manual 모드에 맞춥니다

    상태 표시줄이 ⏸ manual mode on이 되도록 Shift+Tab을 조정합니다. 이 모드에서는 읽기 외의 모든 동작이 승인을 요구하므로 실습하기에 가장 안전합니다.

    여기까지 — 복구 지점과 권한 모드
    • git status가 nothing to commit을 출력했다 (안전장치 ①)
    • 세션이 어떤 모드로 시작했는지 확인하고 4-3 표로 이유를 설명할 수 있다
    • Shift+Tab으로 모드를 순환해 봤고, 지금은 ⏸ manual mode on이다

    작업 트리가 깨끗하지 않으면 여기서 멈추고 먼저 커밋하거나 되돌리세요. 복구 지점 없이 다음 단계로 가면 안전장치 ①이 작동하지 않습니다.

프롬프트 A — 세션 경계 선언

- 내가 명시적으로 요청하기 전에는 어떤 파일도 수정하지 마세요.

예상 출력(응답 예시): 규칙을 확인했다는 짧은 답이 나옵니다. 파일은 전혀 건드리지 않습니다.

성공 확인 방법: 응답이 도착했고 파일 수정 승인 요청이 뜨지 않았다면 성공입니다. 이 프롬프트는 습관을 만드는 것이 목적이므로, 답변 문구 자체는 중요하지 않습니다.

7. 트러블슈팅

설명
증상원인해결
Shift+Tab을 눌러도 auto 모드가 안 나온다 계정이 auto 모드 요건을 충족하지 않거나, 조직에서 꺼 둠 정상 동작일 수 있습니다. Manual과 Plan만으로 이 모듈의 실습을 모두 마칠 수 있습니다. Team·Enterprise라면 관리자가 disableAutoMode로 막았을 수 있으니 문의하세요.
auto 모드인데 자꾸 승인을 묻는다 분류기가 연속 3회 또는 누적 20회 차단하면 auto 모드가 일시 중지되고 다시 묻기 시작함 정상 동작입니다. 묻는 동작을 승인하면 auto 모드가 재개됩니다. 이 임계값은 조정할 수 없습니다.
계획 승인 화면 문구가 문서와 다르다 auto 모드를 쓸 수 없는 세션 첫 선택지가 Yes, auto-accept edits로 표시됩니다. 어느 쪽이든 이 모듈에서는 No, keep planning을 고릅니다.
Plan 모드인데 파일이 바뀌었다 계획을 승인했거나, bypass 권한이 활성화된 세션이라 Plan 모드의 차단이 적용되지 않음 git restore .로 되돌립니다. bypass 권한이 켜진 세션에서는 Plan 모드에서도 편집이 실행되므로, 그 모드로 세션을 시작하지 마세요.
말로 선언한 경계가 무시되는 것 같다 대화가 길어져 컨텍스트가 압축되면서 경계 문장이 사라짐 경계를 다시 선언합니다. 확실한 차단이 필요하면 설정 파일의 deny 규칙이 필요하며, 중급에서 다룹니다.

사실 확인 기준

모드 목록, 시작 모드 기본값, 상태 표시줄 문구, Shift+Tab 순환 순서, 계획 승인 선택지, 분류기의 기본 차단·허용 항목, 보호 경로와 치명 경로, 자동 일시정지 임계값(연속 3회 또는 누적 20회 차단)을 모두 공식 권한 모드 문서로 2026-08-26에 다시 확인했습니다. 권한 모드 6종의 이름·--permission-mode 플래그 값·--dangerously-skip-permissions 관련 경고 문구는 로컬 네이티브 설치본(v2.1.246)에서 claude --help를 직접 실행해 문서와 대조했습니다(CLI 실행 결과 직접 확인, 2026-08-26). 이번 확인에서 4-3 "세션 시작 모드" 표의 순서가 실제 판정 순서와 달랐던 것을 발견해 바로잡았습니다 — 관리자의 disableAutoMode 설정이 가장 먼저 적용되는데도 기존 표에는 맨 아래 줄로 있어, Pro·Max·Team 플랜이 관리자 설정보다 우선하는 것처럼 잘못 읽힐 수 있었습니다. "기준 요금제"의 Pro 이상 조건은 공식 요금제 페이지로 재확인했습니다. 초급 범위를 넘는 모드(dontAsk, bypassPermissions)와 설정 파일 기반 규칙은 같은 문서에서 확인했으나 제외 사유만 적고 실습에서는 다루지 않았습니다.

2026-08-27에는 C-01~C-03의 화면 목업을 만들면서 프롬프트 B를 claude -p --permission-mode plan(v2.1.247)으로 실제 실행했습니다. ExitPlanMode 도구가 비대화 모드에서는 비활성화되어 승인 화면 자체는 뜨지 않았지만, Claude가 텍스트로 요약한 계획을 실제로 받았고 git status로 파일이 바뀌지 않았음을 확인했습니다. C-03 목업의 계획 내용은 이 실행 결과를 옮긴 것입니다. 대화형 상태 표시줄과 승인 선택지 UI 자체는 로그인을 마쳐야 나타나는데, 이 클라우드 환경에는 연결된 브라우저가 없어 로그인을 완료하지 못해 세 캡처 모두 근사 목업으로 대체했습니다.
