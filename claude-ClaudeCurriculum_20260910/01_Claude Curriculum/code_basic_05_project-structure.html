2. 먼저 한 문장으로 이해하기

설명

프로젝트 루트에는 “이 저장소 전체에 관한 입구 설정”이 있고, .claude/ 안에는 Claude Code를 이 프로젝트에 맞게 확장하는 세부 설정이 모입니다.

📘 지침

CLAUDE.md, rules/ — Claude가 프로젝트를 어떻게 이해하고 행동할지 알려줍니다.

⚙️ 설정

settings.json — 권한, hooks, 환경 변수, 모델 기본값 등 실제 클라이언트 동작을 설정합니다.

🧰 확장

skills/, agents/, workflows/, MCP — 반복 작업과 전문 작업자를 추가합니다.

🛡️ 자동화·안전

hooks/의 스크립트를 settings에 연결해 특정 이벤트 전후에 검사·자동화를 실행합니다.

3. 프로젝트 기준 폴더 구조 한눈에 보기

설명
이 그림은 “프로젝트 범위”만 보여줍니다

같은 종류의 설정 중 일부는 개인 전역 범위인 ~/.claude/에도 둘 수 있습니다. 여기서는 팀 저장소를 열었을 때 보게 되는 프로젝트 쪽 구조에 집중합니다.

내 프로젝트
무슨 역할인가
📁project/
Claude Code를 실행하는 프로젝트 루트
📄CLAUDE.md
팀이 공유하는 프로젝트 지침. 세션마다 프로젝트 컨텍스트로 로드됩니다.
📄CLAUDE.local.md
나만 쓰는 프로젝트 지침. 직접 만들었다면 .gitignore에 추가합니다.
📄.gitignore
Git에 올리지 않을 파일을 정합니다. Claude Code 전용 파일은 아니지만 로컬 설정·비밀 파일 관리에 중요합니다.
📄.mcp.json
팀과 공유할 프로젝트 범위 MCP 서버 설정. DB·API·외부 도구를 연결할 때 사용합니다.
📄.worktreeinclude
Claude Code가 새 worktree를 만들 때 함께 복사할 gitignored 파일 패턴을 적습니다.
📁.claude/
이 프로젝트에만 적용할 Claude Code 설정과 확장 기능을 모아두는 핵심 폴더
📁rules/
주제별·경로별 프로젝트 규칙. 특정 파일을 다룰 때만 적용하도록 범위를 줄일 수 있습니다.
📄testing.md
예: 테스트 관련 파일에서만 적용할 규칙
📄api-design.md
예: API·백엔드 코드에서만 적용할 설계 규칙
📁skills/
반복 작업·도메인 지식을 재사용하는 기능. 보통 스킬 하나가 폴더 하나입니다.
📁security-review/
예: 보안 리뷰용 스킬 디렉터리
📄SKILL.md
스킬 본체. 프롬프트와 frontmatter를 적는 중심 파일
📄checklist.md
스킬이 참고할 지원 파일. 스킬은 이런 보조 파일을 함께 둘 수 있습니다.
📁commands/
기존 커스텀 명령 파일. 지금도 동작하지만 custom commands가 skills와 통합되어 새 기능은 skills/ 사용이 권장됩니다.
📄fix-issue.md
예: /fix-issue처럼 파일명으로 실행되는 단일 프롬프트
📁agents/
특정 일만 맡는 커스텀 서브에이전트 정의. 각자 별도 컨텍스트와 도구 구성을 가질 수 있습니다.
📄code-reviewer.md
예: 코드 품질·보안만 검토하도록 만든 전문 리뷰어
📁hooks/
Hook에서 호출할 스크립트를 두기 좋은 관례적 위치. 여기에 넣기만 해서는 실행되지 않습니다.
📄format-on-save.sh
예: PostToolUse 등에 등록해 파일 변경 뒤 자동 포맷
📄block-secrets.sh
예: PreToolUse 등에 등록해 민감 경로나 위험 명령을 검사·차단
📁output-styles/
Claude의 기본 역할·말투·출력 형식을 바꾸는 커스텀 output style
📄teaching.md
예: 설명을 단계적으로 자세히 붙이는 응답 스타일
📁workflows/
많은 서브에이전트를 코드로 조율하는 dynamic workflow 스크립트. 저장한 파일은 /이름으로 다시 실행할 수 있습니다.
📄<name>.js
예: /workflows에서 저장한 JavaScript 워크플로. 고급·대규모 작업용 기능입니다.
📁agent-memory/
서브에이전트가 memory: project를 사용할 때 프로젝트 범위로 누적하는 지속 메모리
📄<agent>/MEMORY.md
서브에이전트가 읽고 갱신하는 메모리 요약 파일. 메모리 기능을 쓸 때 생성·관리됩니다.
📄settings.json
팀 공유 프로젝트 설정의 중심. 권한, hooks, env, 모델, output style 등 여러 Claude Code 설정을 담습니다.
📄settings.local.json
현재 프로젝트에서 나만 쓰는 설정 오버라이드. Claude Code가 저장하면 git에서 제외되도록 처리됩니다.

4. 가장 헷갈리는 차이만 정리하기

설명
헷갈리는 쌍구분 기준
CLAUDE.md vs rules/CLAUDE.md는 거의 모든 세션에서 필요한 핵심 프로젝트 지침. rules/는 주제별로 나누거나 특정 경로에만 적용할 때 좋습니다.
skills/ vs agents/Skill은 해야 할 절차·지식을 재사용하는 것, Agent는 별도 컨텍스트에서 일하는 전문 작업자를 정의하는 것입니다.
agents/ vs workflows/Agent는 작업자 한 명의 정의. Workflow는 여러 agent를 반복·병렬·분기시키는 오케스트레이션 코드입니다.
hooks/ vs settings.jsonhooks/에는 보통 실행 스크립트를 두고, 언제 실행할지는 settings의 hooks 설정이 연결합니다.
settings.json vs settings.local.json팀이 같이 써야 하면 settings.json, 내 컴퓨터에서만 달라야 하면 settings.local.json입니다.
.mcp.json vs settings.json프로젝트에 공유할 MCP 서버 연결은 루트의 .mcp.json. 일반 Claude Code 설정은 .claude/settings.json입니다.

5. “파일이 있다고 자동으로 동작하는가?”

설명

폴더 구조를 외울 때 가장 유용한 기준은 발견되면 자동으로 읽는 것과 설정에서 연결해야 하는 것을 나누는 것입니다.

항목파일만 두면?추가 조건
CLAUDE.md○프로젝트 범위의 적절한 위치에 두면 세션 컨텍스트로 로드
rules/*.md○paths를 쓰면 해당 파일을 다룰 때 조건부 적용
skills/<name>/SKILL.md○사용자 호출 또는 Claude의 관련성 판단으로 실행
agents/*.md○Claude가 위임하거나 사용자가 명시적으로 호출할 때 실행
hooks/*.sh✕settings.json의 hook event에 스크립트 경로를 등록해야 함
output-styles/*.md△/config 또는 outputStyle 설정으로 선택해야 적용
workflows/*.js○Dynamic workflows 기능이 켜져 있어야 하며 저장한 이름으로 호출
agent-memory/✕서브에이전트 정의에서 지속 메모리 범위를 켰을 때 사용

6. 기존 강의와 연결해서 보면

설명

이번 모듈은 모든 기능을 깊게 설정하는 시간이 아니라 “어디에 있는지 아는 지도”입니다. 실제 설정은 아래 강의에서 이어집니다.

  • CLAUDE.md → 초급 04 · CLAUDE.md로 프로젝트 컨텍스트 남기기
  • settings.json → 중급 02 · settings.json으로 반복 승인 정리하기
  • skills/ → 중급 03 · 스킬로 반복 작업 저장하기
  • .mcp.json → 중급 05 · MCP로 외부 도구 연결하기
  • hooks/ → 상급 01 · 훅으로 위험 경로 차단하기
  • agents/ · agent memory → 상급 03 · 서브에이전트로 컨텍스트와 권한 분리하기

7. 7분 확인 실습

실습
  1. 현재 샌드박스에서 Claude 관련 파일을 찾습니다
    셸 명령
    find . -maxdepth 4 \
  \( -name 'CLAUDE.md' -o -name 'CLAUDE.local.md' \
  -o -name '.mcp.json' -o -name '.worktreeinclude' \
  -o -path '*/.claude/*' \) -print

    초급 과정에서는 아직 일부 파일만 보이는 것이 정상입니다. 이 표의 모든 폴더를 미리 만들 필요는 없습니다.

  2. 내가 지금 필요한 기능만 고릅니다

    반복 지침이면 CLAUDE.md/rules, 반복 절차면 skill, 전문 작업자면 agent, 자동 차단이면 hook처럼 목적을 먼저 고르고 그다음 파일 위치를 선택하세요.

  3. 빈 .claude 폴더를 억지로 채우지 않습니다

    공식 문서도 대부분의 사용자는 CLAUDE.md와 settings.json 정도만 직접 편집하고, 나머지는 필요할 때 추가한다고 설명합니다.

8. 기억할 것 5개

  • CLAUDE.md = 프로젝트 지침. 반복해서 설명할 내용을 저장합니다.
  • .claude/settings.json = 프로젝트 설정 중심. 권한·hooks·환경 변수 등 클라이언트 동작을 정합니다.
  • Skill은 절차, Agent는 작업자, Workflow는 작업자들의 실행 순서라고 구분하면 쉽습니다.
  • Hook 스크립트는 폴더에 넣는 것만으로 실행되지 않습니다. settings에서 이벤트와 연결해야 합니다.
  • 모든 폴더를 만들 필요가 없습니다. 필요한 기능이 생길 때 하나씩 추가하는 구조입니다.
