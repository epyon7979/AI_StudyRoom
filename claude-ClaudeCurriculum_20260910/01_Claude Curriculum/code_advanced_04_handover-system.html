2. 학습 목표

설명

이 모듈을 마치면 다음을 할 수 있습니다.

  1. 프로젝트의 컨텍스트 레이어를 목록화하고 각각이 조용히 실패하는 방식을 설명할 수 있다.
  2. 모든 레이어가 살아 있는지 한 번에 점검하고, 세션 시작 시 자동 실행할 수 있다.
  3. 갱신 책임과 주기를 정해 다음 담당자에게 넘길 수 있다.

4. 핵심 개념

설명

4-1. 결론부터

컨텍스트 레이어의 공통 문제는 "틀리는 것"이 아니라 "조용히 없어지는 것"입니다. 상급 01·02·03에서 매번 같은 실패를 재현했습니다 — 훅은 경로 오타로 꺼지고, 안전망은 골든이 안 건드리는 곳을 놓치고, 서브에이전트는 프론트매터 문제로 사라집니다. 어느 것도 세션에 오류를 보고하지 않습니다.

그래서 인계의 핵심은 문서를 잘 쓰는 것이 아니라 "이게 지금 살아 있는가"를 다음 사람이 1초 만에 확인할 수 있게 하는 것입니다.

4-2. 지금까지 만든 여섯 겹

레이어어디서 만들었나언제 로드되나조용히 실패하는 방식
CLAUDE.md초급 04매 세션200줄을 넘겨 준수도가 떨어짐. 낡은 규칙이 전제로 작동
docs/HANDOVER.md중급 01안 됨 — 찾아 읽는 문서아무도 안 읽음. [WEAK]가 확인 안 된 채 방치
settings.json 권한중급 02매 세션JSON 오류로 파일 전체가 무시됨
.claude/skills/중급 03·04필요할 때만description 문제로 자동 호출이 안 됨
.claude/hooks/상급 01·02이벤트마다경로 오타·실행 권한 누락으로 게이트가 꺼짐
.claude/agents/상급 03위임할 때프론트매터 문제로 조용히 건너뛰어짐

여기에 상급 02의 tests/golden/이 더해집니다. 골든이 비면 안전망이 아무것도 검증하지 않으면서 통과합니다.

4-3. 확인 명령이 흩어져 있습니다

각 레이어마다 확인 방법이 다르고, 어느 것도 한꺼번에 보여 주지 않습니다.

레이어확인 방법
CLAUDE.md/context의 Memory files
settings.json/status의 Setting sources, claude doctor
스킬/skills
훅/hooks
서브에이전트@ 타이프어헤드, claude --debug
골든ls tests/golden/

여섯 곳을 매번 돌아보는 사람은 없습니다. 그래서 하나로 묶은 점검 스크립트를 만들고(실습 3단계), 세션 시작 시 자동으로 돌립니다(실습 6단계).

4-4. SessionStart 훅으로 살아 있는 정보를 넣습니다

SessionStart는 세션이 시작되거나 재개될 때 발동하는 훅 이벤트입니다. hookSpecificOutput.additionalContext로 넘긴 문자열이 대화 시작 지점, 첫 프롬프트 앞에 삽입됩니다. (출처: code.claude.com/docs/en/hooks, 2026-08-26 확인)

CLAUDE.md와 역할을 나눠야 합니다

공식 문서가 기준을 제시합니다 — 바뀌지 않는 지시는 CLAUDE.md를 쓰는 편이 낫습니다. 스크립트를 돌리지 않고 로드되며, 정적인 프로젝트 관례를 두는 표준 자리이기 때문입니다. SessionStart 훅은 현재 브랜치, 배포 대상, 최근 CI 결과처럼 지금 상태를 알려 주는 정보에 씁니다. (출처: code.claude.com/docs/en/hooks, 2026-08-26 확인)

"컨텍스트 레이어가 지금 살아 있는가"는 매번 달라지는 상태이므로 훅이 맞습니다.

지시문처럼 쓰면 역효과가 납니다

공식 문서의 경고입니다 — 명령형 시스템 지시가 아니라 사실 서술로 쓰세요. "배포 대상은 프로덕션이다", "이 저장소는 bun test를 쓴다" 같은 표현은 프로젝트 정보로 읽힙니다. 대역 외 시스템 명령처럼 쓴 텍스트는 Claude의 프롬프트 인젝션 방어를 건드려, Claude가 그것을 컨텍스트로 다루지 않고 사용자에게 그대로 보여 주게 만듭니다. (출처: code.claude.com/docs/en/hooks, 2026-08-26 확인)

그래서 이 모듈의 점검 결과도 "OK CLAUDE.md: 5줄"처럼 상태를 서술합니다.

4-5. 재개할 때는 다시 돌지만, 과거 턴은 그대로입니다

주입한 텍스트는 세션 트랜스크립트에 저장됩니다. --continue나 --resume으로 재개하면 과거 턴에 대해서는 훅을 다시 실행하지 않고 저장된 텍스트를 재생하므로, 타임스탬프나 커밋 해시 같은 값은 낡습니다. 다만 SessionStart 훅은 재개 시 source가 "resume"으로 다시 실행되어 컨텍스트를 갱신할 수 있습니다. (--fork-session으로 분기했다면 source는 "fork"입니다.) (출처: code.claude.com/docs/en/hooks, 2026-08-26 확인)

4-6. 인계의 진짜 어려움은 갱신 책임입니다

낡은 컨텍스트가 없는 컨텍스트보다 위험합니다

CLAUDE.md에 적힌 규칙이 6개월 전 사실이면, Claude는 그것을 지금 사실로 전제하고 작업합니다. 훅은 이미 없어진 파일을 지키고, 리뷰 스킬은 바뀐 규칙으로 지적하고, 서브에이전트는 옮겨진 진입점을 찾습니다.

레이어를 만드는 것보다 갱신 규칙을 정하는 것이 어렵습니다. 그래서 이 모듈의 결과물에는 스크립트뿐 아니라 "누가 언제 무엇을 갱신하는가"가 포함됩니다.

갱신 계기무엇을 손보나
같은 실수가 두 번째 나올 때CLAUDE.md에 사실 추가, 절차면 스킬로
[WEAK]·[GUESS]가 확인될 때HANDOVER 라벨 승격, 필요하면 훅으로 강제
보호 대상이 이동·삭제될 때훅 경로와 골든 갱신
의도한 동작 변경을 승인할 때골든 재캡처 (상급 02)
담당자가 바뀔 때전체 점검 실행 + 확인 필요 항목 인계

예제 코드 ① — 통합 점검 스크립트 전문

사전 준비물: 4-2의 여섯 레이어가 갖춰진 샌드박스, python3. 외부 패키지 없음.

.claude/hooks/preflight.py — 발췌가 아닌 전문입니다
#!/usr/bin/env python3
"""컨텍스트 레이어가 전부 살아 있는지 한 번에 점검한다.
--hook을 붙이면 SessionStart용 JSON을, 붙이지 않으면 사람이 읽는 보고서를 낸다."""
import json
import os
import pathlib
import re
import sys

ROOT = pathlib.Path(os.environ.get("CLAUDE_PROJECT_DIR") or ".").resolve()


def check_claude_md():
    p = ROOT / "CLAUDE.md"
    if not p.exists():
        return False, "CLAUDE.md 없음"
    n = len(p.read_text(encoding="utf-8").splitlines())
    if n > 200:
        return False, f"CLAUDE.md {n}줄 — 200줄 기준 초과"
    return True, f"CLAUDE.md {n}줄"


def check_handover():
    p = ROOT / "docs" / "HANDOVER.md"
    if not p.exists():
        return False, "docs/HANDOVER.md 없음"
    t = p.read_text(encoding="utf-8")
    labels = {l: t.count(f"[{l}]") for l in ("FACT", "STRONG", "WEAK", "GUESS")}
    if sum(labels.values()) == 0:
        return False, "HANDOVER.md에 신뢰도 라벨 없음"
    open_q = labels["WEAK"] + labels["GUESS"]
    return True, f"HANDOVER.md 라벨 {sum(labels.values())}건 (확인 필요 {open_q}건)"


def check_settings():
    p = ROOT / ".claude" / "settings.json"
    if not p.exists():
        return False, ".claude/settings.json 없음"
    try:
        cfg = json.loads(p.read_text(encoding="utf-8"))
    except json.JSONDecodeError as e:
        return False, f"settings.json 파싱 실패 (line {e.lineno}) — 설정 전체가 무시됨"
    events = list((cfg.get("hooks") or {}).keys())
    return True, f"settings.json 유효, 훅 이벤트 {len(events)}개: {', '.join(events) or '없음'}"


def check_hook_scripts():
    p = ROOT / ".claude" / "settings.json"
    if not p.exists():
        return False, "settings.json 없어 훅 경로를 확인할 수 없음"
    try:
        cfg = json.loads(p.read_text(encoding="utf-8"))
    except json.JSONDecodeError:
        return False, "settings.json 파싱 실패로 훅 경로 확인 불가"
    missing, checked = [], 0
    for groups in (cfg.get("hooks") or {}).values():
        for g in groups:
            for h in g.get("hooks", []):
                cmd = h.get("command", "")
                if not cmd or h.get("type") != "command":
                    continue
                path = pathlib.Path(cmd.replace("${CLAUDE_PROJECT_DIR}", str(ROOT)))
                checked += 1
                if not path.exists():
                    missing.append(f"{path.name} 없음")
                elif not os.access(path, os.X_OK):
                    missing.append(f"{path.name} 실행 권한 없음")
    if missing:
        return False, f"훅 스크립트 문제: {', '.join(missing)} — 게이트가 조용히 꺼진 상태"
    return True, f"훅 스크립트 {checked}개 모두 존재·실행 가능"


def check_skills():
    d = ROOT / ".claude" / "skills"
    if not d.exists():
        return True, "스킬 없음"
    bad, ok = [], 0
    for sk in sorted(d.iterdir()):
        if not sk.is_dir():
            continue
        f = sk / "SKILL.md"
        if not f.exists():
            bad.append(f"{sk.name}: SKILL.md 없음"); continue
        t = f.read_text(encoding="utf-8")
        if not t.startswith("---"):
            bad.append(f"{sk.name}: 프론트매터 없음"); continue
        if not re.search(r"^description:\s*\S", t, re.M):
            bad.append(f"{sk.name}: description 없음 — 자동 호출 안 됨"); continue
        ok += 1
    return (not bad), (f"스킬 {ok}개 정상" if not bad else f"스킬 문제: {'; '.join(bad)}")


def check_agents():
    d = ROOT / ".claude" / "agents"
    if not d.exists():
        return True, "서브에이전트 없음"
    bad, ok = [], 0
    for f in sorted(d.glob("*.md")):
        t = f.read_text(encoding="utf-8")
        m = re.match(r"^---\n(.*?)\n---\n", t, re.S)
        if not m:
            bad.append(f"{f.name}: 프론트매터 없음 — 조용히 건너뜀"); continue
        fm = m.group(1)
        nm = re.search(r"^name:\s*(\S+)", fm, re.M)
        if not nm:
            bad.append(f"{f.name}: name 없음 — 문서로 취급됨"); continue
        name = nm.group(1)
        if name.startswith("-") or ":" in name or not re.fullmatch(r"[a-z][a-z-]*", name):
            bad.append(f"{f.name}: name '{name}' 형식 오류 — 조용히 건너뜀"); continue
        if not re.search(r"^description:\s*\S", fm, re.M):
            bad.append(f"{f.name}: description 없음 — 조용히 건너뜀"); continue
        ok += 1
    return (not bad), (f"서브에이전트 {ok}개 정상" if not bad else f"서브에이전트 문제: {'; '.join(bad)}")


def check_golden():
    d = ROOT / "tests" / "golden"
    if not d.exists():
        return True, "특성화 테스트 없음"
    n = len(list(d.glob("*.txt")))
    if n == 0:
        return False, "tests/golden 비어 있음 — 안전망이 아무것도 검증하지 않음"
    return True, f"골든 {n}건"


CHECKS = [
    ("CLAUDE.md", check_claude_md),
    ("HANDOVER", check_handover),
    ("settings.json", check_settings),
    ("훅 스크립트", check_hook_scripts),
    ("스킬", check_skills),
    ("서브에이전트", check_agents),
    ("골든 파일", check_golden),
]


def run():
    results = []
    for label, fn in CHECKS:
        try:
            ok, msg = fn()
        except Exception as e:
            ok, msg = False, f"점검 중 오류: {e}"
        results.append((label, ok, msg))
    return results


def main():
    # 훅으로 실행할 때는 --hook을 붙인다. 붙이지 않으면 사람이 읽는 보고서를 낸다.
    hook_mode = "--hook" in sys.argv
    if hook_mode:
        try:
            json.load(sys.stdin)
        except Exception:
            pass

    results = run()
    failed = [r for r in results if not r[1]]

    if hook_mode:
        lines = [f"{'OK' if ok else '문제'} {label}: {msg}" for label, ok, msg in results]
        summary = "컨텍스트 레이어 점검 결과\n" + "\n".join(lines)
        if failed:
            summary += ("\n\n위 '문제' 항목은 오류를 표시하지 않고 조용히 동작하지 않는 상태입니다. "
                        "사용자에게 먼저 알리고, 고치기 전에는 이 레이어가 지켜 준다고 가정하지 마세요.")
        json.dump({"hookSpecificOutput": {
            "hookEventName": "SessionStart",
            "additionalContext": summary,
        }}, sys.stdout, ensure_ascii=False)
        return 0

    for label, ok, msg in results:
        print(f'{"OK  " if ok else "!!  "}{label:14s} {msg}')
    print()
    print("전체:", "ALL PASS" if not failed else f"{len(failed)}건 문제")
    return 0 if not failed else 1


if __name__ == "__main__":
    sys.exit(main())

설계 판단을 이렇게 했습니다:

선택이유
--hook 명시 플래그로 모드 구분터미널 유무로 판별하면 CI나 파이프 환경에서 예측 불가하게 동작합니다
메시지에 결과까지 서술 ("게이트가 조용히 꺼진 상태")"파일 없음"만으로는 심각성을 모릅니다. 다음 사람이 판단할 수 있게 씁니다
사람 모드에서 종료 코드 1CI나 pre-commit에 그대로 꽂을 수 있습니다(모듈 05에서 활용)
각 점검을 try로 감쌈점검 하나가 죽어 나머지 점검이 안 도는 것이 가장 나쁩니다
없는 레이어는 통과 처리스킬이나 에이전트를 안 쓰는 프로젝트에서 가짜 실패를 만들지 않습니다
훅 모드 메시지를 사실 서술로명령형으로 쓰면 프롬프트 인젝션 방어에 걸립니다(4-4)

예상 출력: 정상 상태에서 7줄과 전체: ALL PASS, 종료 코드 0.

성공 확인 방법: 아래 3가지를 모두 확인합니다.

성공 확인 방법: 각 항목에 코드 근거가 붙어 있거나 "코드로 판정 불가"로 표시되면 성공입니다. 근거 없이 "낡았을 수 있다"고만 하면 중급 01의 신뢰도 라벨 원칙을 다시 적용해 요청하세요. 결과는 docs/CONTEXT-MAP.md에 덧붙입니다.

7. 트러블슈팅

설명
증상원인해결
새 세션에서 Claude가 점검 결과를 모른다 SessionStart 훅이 등록되지 않았거나 조용히 실패 /hooks에 SessionStart가 보이는지 확인합니다. 상급 01의 7번 절과 원인이 같습니다.
손상 상태인데 Claude가 아무것도 모른다 --hook 플래그를 안 붙여 사람용 출력이 나감. 정상 상태(종료 코드 0)라면 평문도 그대로 컨텍스트에 들어가 문제가 안 드러나지만, 손상 상태(종료 코드 1)에서는 Claude Code가 이를 훅 오류로 처리해 출력을 통째로 버립니다. 그래서 이 증상은 꼭 손상 상태에서만 나타납니다. args에 ["--hook"]이 있는지 확인합니다. CLAUDE_PROJECT_DIR=$(pwd) python3 .claude/hooks/preflight.py --hook를 직접 실행해 hookSpecificOutput JSON이 나오는지 먼저 확인하세요. (출처: CLI 실행 결과 직접 확인, 2026-08-26 — 정상 상태에서는 --hook 없이도 평문이 Claude 컨텍스트에 반영됐지만, 손상 상태(종료 코드 1)에서는 --debug-file 로그에 "Hook SessionStart … error"로 기록되고 Claude는 점검 결과를 전혀 받지 못했습니다.)
세션 시작이 눈에 띄게 느려졌다 점검이 무거움 SessionStart는 모든 세션에서 돌므로 빠르게 유지해야 합니다. 파일 존재 확인 수준을 넘지 마세요. 테스트 실행 같은 무거운 것은 PostToolUse(상급 02)에 둡니다.
재개했더니 점검 결과가 예전 것이다 과거 턴은 저장된 텍스트를 재생함 정상 동작입니다(4-5). SessionStart 훅 자체는 재개 시 source: "resume"으로 다시 돌아 새 결과를 넣습니다.
주입한 텍스트가 화면에 그대로 표시된다 명령형 지시처럼 써서 프롬프트 인젝션 방어에 걸림 사실 서술로 바꿉니다(4-4). "…하세요"가 아니라 "…상태입니다" 형태로 씁니다.

7-2. 흔한 잘못된 습관

습관겉으로 나타나는 모습대응
인계 문서를 쓰고 검증은 안 만든다 문서가 훌륭해 보임. 다음 사람이 클론했을 때 절반이 이미 꺼져 있음 문서보다 점검 스크립트가 먼저입니다. 문서는 스크립트가 못 잡는 것을 담습니다.
레이어를 늘리기만 한다 안전해 보임. 갱신 대상이 늘어 아무도 관리하지 못함 레이어를 추가할 때 갱신 계기를 함께 정합니다(4-6). 정할 수 없으면 만들지 않습니다.
[WEAK]를 확인하지 않고 방치한다 당장 문제없음. 확인 안 된 추측이 몇 달 뒤 사실처럼 인용됨 점검 스크립트가 확인 필요 건수를 매번 보여 주게 했습니다. 담당자 교체 시 반드시 인계하세요.
낡은 규칙을 지우지 않는다 지우기 아까움. Claude가 없어진 파일을 지키고 바뀐 규칙으로 지적함 프롬프트 B를 주기적으로 돌립니다. 낡은 컨텍스트는 없는 컨텍스트보다 위험합니다(4-6).

사실 확인 기준

SessionStart가 세션 시작·재개 시 발동한다는 점, additionalContext가 대화 시작 지점·첫 프롬프트 앞에 삽입된다는 점, 바뀌지 않는 지시는 CLAUDE.md가 낫다는 권고, 명령형이 아닌 사실 서술로 써야 프롬프트 인젝션 방어에 걸리지 않는다는 안내, 재개 시 과거 턴은 저장된 텍스트를 재생하고 SessionStart는 source: "resume"(포크 시 "fork")으로 다시 실행된다는 점, 매처를 생략하면 startup·resume·clear·compact·fork 모든 시작 유형에서 발동한다는 점, SessionStart 훅을 빠르게 유지하라는 권고, /context의 Memory files·/status의 Setting sources·/hooks 메뉴·서브에이전트 프론트매터의 name·description 필수 요건을 모두 공식 문서로 확인했습니다.
