2. 학습 목표

설명

이 모듈을 마치면 다음을 할 수 있습니다.

  1. MCP 서버의 3개 스코프 차이를 설명하고 상황에 맞는 스코프를 고를 수 있다.
  2. claude mcp 명령으로 서버를 등록·조회·제거하고 상태를 확인할 수 있다.
  3. 자격 증명을 저장소에 남기지 않는 방식으로 서버를 설정할 수 있다.

3-3. 실습용 MCP 서버는 조직이 정합니다

이 모듈에는 공식 자료 미확인 항목이 있습니다

이 커리큘럼은 특정 MCP 서버 패키지를 지정하지 않습니다. 서버는 대부분 외부에서 배포되고, 이름·설치 방법·필요 권한이 바뀔 수 있어 공식 자료로 고정할 수 없기 때문입니다. 검증되지 않은 패키지 이름을 교재에 박아 두면 학습자가 그대로 따라 하다 잘못된 것을 설치할 위험이 있습니다.

교육 담당자가 아래를 정해 이 절을 채워 주세요.

  • 실습에 쓸 서버 (사내 승인 목록에서 선택)
  • 그 서버의 등록 명령 전문
  • 연결 성공을 확인할 방법 (어떤 도구가 보이면 성공인지)

정해지기 전까지 이 모듈은 등록·조회·제거의 생애주기와 스코프 선택을 실습합니다. 그 부분만으로도 5번 절의 실습은 완결됩니다.

사내 시스템에 연결하기 전에

MCP 서버는 Claude에게 외부 시스템에 대한 실제 권한을 줍니다. 운영 DB나 티켓 시스템에 붙이기 전에 반드시 확인하세요. ① 읽기 전용 계정으로 붙일 수 있는가 ② 사내 보안 정책이 이 연결을 허용하는가 ③ 자격 증명이 저장소에 들어가지 않는가(4-5).

4. 핵심 개념

설명

4-1. 결론부터

MCP에서 가장 중요한 결정은 "무엇을 연결하느냐"가 아니라 "어디에 등록하느냐"입니다. 스코프를 잘못 고르면 자격 증명이 저장소에 커밋되거나, 팀원 모두에게 예상치 못한 서버가 로드됩니다.

4-2. 스코프 3가지

스코프는 서버가 어느 프로젝트에서 로드되는지와 팀과 공유되는지를 결정합니다. (출처: code.claude.com/docs/en/mcp, 2026-08-26 확인)

스코프저장 위치적용 범위쓰는 상황
local (기본값)~/.claude.json의 해당 프로젝트 경로 아래추가한 그 프로젝트에서만, 나에게만개인 개발용 서버, 실험, 버전 관리에 넣고 싶지 않은 자격 증명
project저장소 루트의 .mcp.json커밋하면 팀 전체팀이 함께 쓰는 서버
user~/.claude.json (전역)내 모든 프로젝트어디서나 쓰는 개인 유틸리티
"local"이라는 말이 두 곳에서 다르게 쓰입니다

MCP의 local 스코프는 ~/.claude.json(홈 디렉터리)에 저장됩니다. 반면 중급 02에서 배운 프로젝트 로컬 설정은 .claude/settings.local.json(프로젝트 디렉터리)입니다. 이름은 비슷하지만 다른 파일입니다. (출처: code.claude.com/docs/en/mcp, 2026-08-26 확인)

4-3. 등록 명령의 문법

모든 claude mcp add 명령은 --scope project나 --scope user를 붙이지 않으면 local 스코프에 씁니다. (출처: code.claude.com/docs/en/mcp, 2026-08-26 확인)

기본 문법
claude mcp add [옵션] <이름> <실행 명령 또는 URL> [인자...]
규칙내용
옵션 위치--transport·--env·--scope·--header는 <이름>의 앞이든 뒤든 위치와 무관하게 인식됩니다. 유일한 경계는 --입니다 — 그 뒤에 오는 내용만 "Claude의 옵션이 아니라 실행 명령"으로 취급됩니다. (직접 확인: claude mcp add practice-project --scope project -- echo ...와 claude mcp add --scope project practice-project -- echo ...가 동일하게 동작함)
-- 구분자local stdio 서버를 등록할 때, 실행 명령에 -y처럼 하이픈으로 시작하는 인자가 있다면 반드시 필요합니다. 빠뜨리면 Claude Code가 그 인자를 자기 옵션으로 읽어 error: unknown option '-y'로 실패합니다. 인자가 하이픈으로 시작하지 않으면 생략해도 동작하지만, 습관적으로 붙이는 편이 안전합니다
원격 서버URL이면 원격입니다. --transport를 생략하면 기본값은 stdio이므로, https:// 서버는 반드시 --transport http를 명시해야 합니다

SSE 전송 방식은 공식적으로 지원 중단(deprecated)되었습니다. 가능하면 HTTP(스트리머블 HTTP) 서버를 쓰세요. 연결 오류가 나면 --transport http로 바꿔 보세요. (출처: code.claude.com/docs/en/mcp, 2026-08-26 확인)

4-4. 프로젝트 스코프는 승인을 거칩니다

.mcp.json은 저장소를 클론하면 따라옵니다. 즉 내가 등록하지 않은 서버가 내 기기에서 실행될 수 있습니다. 그래서 프로젝트 스코프 서버는 처음 쓸 때 승인을 요구합니다.

이건 성가신 절차가 아니라 안전장치입니다

클론한 저장소의 .mcp.json에 무엇이 들어 있는지 모른 채 실행하면, 그 서버가 무엇을 하는지도 모른 채 Claude에게 권한을 주는 셈입니다. 승인 화면이 뜨면 실행 명령과 환경 변수를 반드시 읽으세요. 초급 03에서 배운 승인 화면 읽기 습관이 여기서도 똑같이 적용됩니다.

4-5. 자격 증명을 저장소에 남기지 않는 법

방법어떻게언제
local 스코프에 등록기본값 그대로 등록하면 ~/.claude.json에만 저장됨나만 쓰는 서버. 가장 단순하고 안전
환경 변수 참조.mcp.json에는 ${VAR} 형태만 두고 실제 값은 셸 환경에 둠팀과 설정은 공유하되 값은 각자 관리할 때
가장 흔한 사고

--scope project로 등록하면서 --env에 실제 토큰을 그대로 넣고 .mcp.json을 커밋하는 것입니다. 이 파일은 평문이고 저장소에 남습니다. 등록 후 반드시 cat .mcp.json으로 무엇이 파일에 들어갔는지 직접 눈으로 확인하세요. 실습 6단계에서 이것을 연습합니다.

4-6. 알아 둘 명령

명령구분하는 일
claude mcp add셸서버 등록
claude mcp list셸등록된 서버 목록과 상태
claude mcp get <이름>셸한 서버의 상세 설정
claude mcp remove <이름>셸서버 제거
/mcp세션서버 상태 확인과 OAuth 인증 처리

5. 단계별 실습

실습

만들 결과물: 스코프별 저장 위치를 직접 확인한 기록과, 정리까지 마친 깨끗한 상태.

이 실습은 서버 없이도 완결됩니다

3-3에서 조직이 서버를 정했다면 그 등록 명령을 5·6단계에 넣어 진행하세요. 아직 정해지지 않았다면 아래 그대로 진행해도 스코프·저장 위치·생애주기는 전부 실습됩니다.

  1. 현재 등록된 서버를 확인합니다
    셸 명령
    cd ~/claude-code-sandbox
claude mcp list

    아무것도 없으면 정상입니다. 이것이 대조군입니다.

  2. 저장 파일의 현재 상태를 확인합니다

    등록 전에 무엇이 있는지 봐 둡니다. 6단계에서 비교합니다.

    셸 명령
    ls .mcp.json 2>/dev/null || echo ".mcp.json 없음"
grep -c mcpServers ~/.claude.json 2>/dev/null || echo "~/.claude.json 확인 불가"
  3. local 스코프로 서버를 등록합니다

    스코프를 지정하지 않으면 local입니다(4-3). 조직이 정한 서버가 있으면 그 명령을, 없으면 아래 연습용 명령을 씁니다.

    셸 명령 (연습용 — 실제 동작하는 서버는 아닙니다)
    claude mcp add practice-local -- echo "mcp practice"
    이 서버는 연결되지 않습니다

    echo는 MCP 서버가 아니므로 claude mcp list에서 연결 실패로 표시되는 것이 정상입니다. 이 단계의 목적은 연결이 아니라 등록이 어디에 저장되는지 확인하는 것입니다.

  4. 등록 결과와 저장 위치를 확인합니다
    셸 명령
    claude mcp list
claude mcp get practice-local
ls .mcp.json 2>/dev/null || echo ".mcp.json 여전히 없음"

    .mcp.json이 안 생긴 것이 핵심입니다. local 스코프는 저장소가 아니라 ~/.claude.json에 저장되므로 커밋될 일이 없습니다(4-2).

    여기까지 — local 스코프
    • claude mcp list에 practice-local이 보인다 (연결 상태는 실패여도 정상)
    • 저장소에 .mcp.json이 생기지 않았다
    • 스코프를 지정하지 않으면 local이라는 것을 확인했다

    .mcp.json이 생겼다면 --scope project를 붙였을 가능성이 큽니다. 7번 절을 확인하세요.

  5. project 스코프로 하나 더 등록합니다
    셸 명령
    claude mcp add practice-project --scope project -- echo "mcp practice"
  6. 파일에 무엇이 들어갔는지 직접 봅니다

    4-5에서 강조한 습관입니다. 등록했으면 파일을 열어 봅니다.

    셸 명령 · 예상 출력
    $ cat .mcp.json
{
  "mcpServers": {
    "practice-project": {
      "type": "stdio",
      "command": "echo",
      "args": [
        "mcp practice"
      ],
      "env": {}
    }
  }
}

$ git status --short
?? .mcp.json

    .mcp.json이 저장소에 생겼고 git이 새 파일로 인식합니다. 여기에 실제 토큰이 들어 있었다면 커밋하는 순간 저장소에 남습니다. (CLI 실행 결과 직접 확인, Claude Code v2.1.246, 2026-08-26)

    [캡처 C-01]
    화면
    claude mcp list의 서버 목록
    진입 경로
    두 서버를 등록한 뒤 터미널에서 claude mcp list
    캡처 범위
    등록된 서버와 각각의 상태가 보이는 범위
    강조 표시
    두 서버의 상태 표시 차이 — practice-project의 ⏸ Pending approval과 practice-local의 ✘ Failed to connect(빨간 테두리)
    캡션
    같은 명령이라도 --scope에 따라 저장 위치와 승인 절차가 달라진다.
    화면 캡처 대신 실제 실행 결과

    claude mcp list는 셸에서 바로 실행되는 명령이라(슬래시 커맨드가 아님) 이 환경에서도 화면과 동일한 진짜 결과를 그대로 얻을 수 있었습니다. 아래는 같은 절차로 재구성한 샌드박스에서 practice-local(local 스코프)·practice-project(project 스코프)를 등록한 뒤 claude mcp list를 실제 실행한 출력 그대로입니다(2026-08-27, Claude Code v2.1.247).

    이 자리에서 바로잡은 것

    실제로 실행해 보니 claude mcp list는 "local"·"project" 같은 스코프 이름을 문자 그대로 표시하지 않습니다. claude mcp list --help·claude mcp get --help로 직접 확인한 공식 동작은 "프로젝트 .mcp.json의 미승인 서버는 ⏸ Pending approval로 표시되고 아직 연결을 시도하지 않는다"는 것입니다. 즉 아래 목록에서 practice-project만 ⏸ Pending approval로 나오고 practice-local은 곧바로 연결을 시도해 실패로 나오는 이 차이 자체가 스코프를 구분하는 신호입니다. 스코프 이름을 문자 그대로 보려면 claude mcp get <이름>을 쓰세요 — 아래 6번 절 실행 결과에 Scope: Local config (private to you in this project)처럼 그대로 나옵니다. 위 캡처 지시서의 "강조 표시"도 이에 맞춰 고쳤습니다. (CLI 실행 결과 및 --help 직접 확인, Claude Code v2.1.247, 2026-08-27)

    셸 명령 · 실제 출력 (두 서버 등록 후)
    $ claude mcp list
Checking MCP server health…

practice-project: echo mcp practice - ⏸ Pending approval (run `claude` to approve)
practice-local: echo mcp practice - ✘ Failed to connect — CONNECTION_CLOSED: Connection closed

    연결 실패 메시지의 정확한 문구(에러 코드 표기 등)는 실행 환경·타이밍에 따라 달라질 수 있는 응답 예시입니다. 확인 기준은 문구가 아니라 practice-project는 Pending approval로, practice-local은 바로 연결 시도 후 실패로 나오는지입니다.

    여기까지 — 스코프 차이 확인
    • local 서버는 저장소에 파일을 만들지 않았다
    • project 서버는 .mcp.json을 만들었고 git이 인식한다
    • 두 파일의 차이를 직접 눈으로 봤다

    이 차이가 이 모듈의 핵심입니다. 자격 증명이 들어가는 서버라면 local을 기본으로 삼으세요.

  7. 세션에서 상태를 확인합니다

    claude로 세션을 엽니다. practice-project는 이 디렉터리에서 아직 승인한 적 없는 project 스코프 서버이므로, 세션이 열리며 승인 여부를 묻는 화면이 먼저 뜰 수 있습니다(4-4). 실행 명령(echo mcp practice)을 확인하고 승인한 뒤 아래를 입력합니다.

    세션 커맨드
    /mcp

    local 서버(practice-local)는 연결 실패로 나옵니다. project 서버는 승인하지 않았다면 승인 대기로, 승인했다면 마찬가지로 연결 실패로 나옵니다 — echo가 실제 MCP 서버가 아니기 때문입니다. 실제 서버라면 여기서 도구 목록과 OAuth 인증 항목을 볼 수 있습니다.

  8. 정리합니다

    연습용 서버 두 개를 제거하고 파일도 지웁니다.

    셸 명령
    claude mcp remove practice-local
claude mcp remove practice-project
rm -f .mcp.json
claude mcp list

    목록이 다시 비면 완료입니다. 조직이 정한 실제 서버를 쓰는 경우 제거하지 말고 남겨 두세요.

  9. 최종 상태를 확인합니다
    셸 명령 · 예상 출력
    $ git status
On branch main
nothing to commit, working tree clean

    작업 트리가 깨끗하면 코스 종료 준비가 된 것입니다.

6. 예제 코드·예제 프롬프트

실습 자료

예제 코드 — 등록·확인·제거 생애주기

사전 준비물: 샌드박스 디렉터리, Claude Code 설치 완료. 외부 네트워크는 필요 없습니다.

실행할 명령 전문 — 순서대로 실행하세요
# 1. 등록 전 상태
claude mcp list

# 2. local 스코프 등록 (스코프를 지정하지 않으면 local)
claude mcp add practice-local -- echo "mcp practice"

# 3. project 스코프 등록
claude mcp add practice-project --scope project -- echo "mcp practice"

# 4. 저장 위치 확인 — 이 단계가 핵심
claude mcp list
cat .mcp.json
git status --short

# 5. 정리
claude mcp remove practice-local
claude mcp remove practice-project
rm -f .mcp.json
claude mcp list

예상 출력: 2·3번은 각각 Added stdio MCP server practice-local ... to local config / ... practice-project ... to project config 형태의 등록 완료 메시지가 나옵니다. 4번의 claude mcp list는 두 서버를 보여 주지만 상태 문구가 서로 다릅니다. local 서버(practice-local)는 × Failed to connect — CONNECTION_CLOSED: Connection closed로 표시되고, project 서버(practice-project)는 이 디렉터리에서 아직 claude를 대화형으로 실행해 승인한 적이 없으므로 ⏸ Pending approval (run `claude` to approve)로 표시됩니다. 문구는 다르지만 둘 다 "실제로 연결되지 않았다"는 같은 사실을 나타냅니다 — echo는 MCP 서버가 아니고, project 서버는 아직 승인 절차를 거치지 않았기 때문입니다. cat .mcp.json은 mcpServers 아래 practice-project만 담긴 JSON을 출력하고, git status --short는 ?? .mcp.json을 표시합니다. 5번 후 목록이 비웁니다. (CLI 실행 결과 직접 확인, Claude Code v2.1.246, 2026-08-26)

성공 확인 방법: 아래 3가지가 맞으면 성공입니다.

조직이 실제 서버를 정한 경우

2번의 echo 부분을 조직이 정한 등록 명령으로 바꾸고, 4번의 확인에 "어떤 도구가 보이면 성공인지"를 추가하세요. 5번의 정리는 하지 않습니다.

프롬프트 A — 연결된 도구 확인

사전 준비물: 실제 MCP 서버가 연결된 세션. 연습용 echo 서버로는 이 프롬프트가 의미 있는 결과를 내지 않습니다.

실행할 프롬프트 전문
지금 사용할 수 있는 MCP 도구를 목록으로 알려 주세요.
각 도구가 무엇을 하는지 한 줄씩 덧붙여 주세요.

예상 출력(응답 예시): 연결된 서버가 제공하는 도구 이름과 설명이 나열됩니다. 연결된 서버가 없으면 없다고 답합니다.

성공 확인 방법: /mcp에서 본 서버의 도구가 목록에 나타나면 성공입니다. 서버는 연결됐는데 도구가 0개라면 인증이 필요한 상태일 수 있으니 /mcp에서 인증 항목을 확인하세요.

7. 트러블슈팅

설명
증상원인해결
의도치 않게 .mcp.json이 생겼다 --scope project를 붙였음 claude mcp remove <이름>으로 제거하고 .mcp.json을 지웁니다. 스코프를 빼면 local이 기본입니다(4-3).
서버에 넘길 플래그를 Claude Code가 자기 옵션으로 읽는다 -- 구분자를 빠뜨림 실행 명령 앞에 --를 넣습니다(예: claude mcp add my-server -- npx -y my-server). --transport·--env·--scope 같은 옵션은 이름 앞뒤 어디에 둬도 동작하지만, -- 뒤에 오는 것은 전부 그대로 서버 실행 명령으로 전달됩니다(4-3).
클론한 저장소의 서버가 승인 대기 상태다 프로젝트 스코프 서버는 첫 사용 전 승인이 필요함 정상 동작입니다. claude를 대화형으로 실행해 승인 화면에서 실행 명령과 환경 변수를 읽고 결정하세요(4-4).
서버는 연결됐는데 도구가 0개다 인증이 필요하거나, 세션 중간에 추가함 세션에서 /mcp를 열어 인증 항목을 확인합니다. 세션 중에 추가한 stdio 서버는 새 세션에서 도구가 잡힙니다.
토큰을 .mcp.json에 넣고 커밋해 버렸다 project 스코프에 실제 값을 직접 넣음 즉시 해당 토큰을 폐기하고 재발급하세요. 파일에서 지우는 것만으로는 git 이력에 남습니다. 사내 보안 담당자에게 알리고, 앞으로는 local 스코프나 환경 변수 참조를 씁니다(4-5).

7-2. 흔한 잘못된 습관

습관겉으로 나타나는 모습대응
등록만 하고 파일을 안 열어 본다 잘 동작하니 문제없어 보임. 어느 날 저장소에서 토큰이 발견됨 등록 직후 cat .mcp.json과 git status를 습관으로 만듭니다(6단계).
편하다고 전부 project 스코프로 등록한다 팀원들이 다 쓸 수 있어 좋아 보임. 자격 증명이 저장소에 쌓임 기본은 local입니다. 팀 공유가 실제로 필요한 것만 project로 올립니다(4-2).
클론한 저장소의 승인 화면을 읽지 않고 넘긴다 빨리 일할 수 있음. 무엇이 실행되는지 모른 채 권한을 줌 실행 명령과 환경 변수를 읽고 결정합니다. 모르는 서버면 저장소 작성자에게 먼저 물어보세요(4-4).
운영 계정으로 붙인다 필요한 데이터가 다 보여 편함. 사고 시 피해 범위가 최대 읽기 전용·최소 권한 계정으로 시작합니다(3-3의 경고).

C-01 완성(2026-08-27)

claude mcp list는 셸 서브커맨드라 이 환경에서도 화면과 동일한 실제 결과를 얻을 수 있었습니다. 같은 절차로 재구성한 샌드박스에서 local·project 두 서버를 실제 등록해 claude mcp list 전문을 그대로 실었고, 그 과정에서 이 목록이 "local"·"project" 같은 스코프 이름을 문자 그대로 보여주지는 않는다는 것을 claude mcp list --help로 재확인해 캡처 지시서의 "강조 표시" 항목을 status 차이(Pending approval vs Failed to connect) 기준으로 고쳤습니다.
