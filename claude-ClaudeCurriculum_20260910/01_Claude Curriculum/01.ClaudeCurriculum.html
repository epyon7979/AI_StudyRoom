오늘의 실습 진행 문서

오늘 이 문서를 따라 함께 실습합니다. 프롬프트와 명령은 그대로 복사해서 쓰시면 됩니다. Claude 개인화 → 메타 프롬프팅 → Claude Code(폴더 구조·권한·훅) → 강사의 SM 실무 사례 순서로 진행됩니다.

1. 이 문서 사용법

안내
  • 진행 순서대로 위에서 아래로 따라가면 됩니다.
  • 회색 코드 상자는 그대로 입력하는 명령·프롬프트입니다. 복사해서 붙여 넣으세요.
  • Claude의 응답 문구는 실행할 때마다 달라집니다. 각 실습의 "확인 기준"은 문구가 아니라 결과의 형태·존재 여부로 판단하세요.
  • 각 블록 끝의 체크포인트를 통과했는지 스스로 확인한 뒤 다음 블록으로 넘어가세요.
  • 오늘 다루지 않는 내용은 마지막 절에 자습 일정으로 정리되어 있습니다.

2. 오늘의 목표

설명

오늘을 마치면 다음을 할 수 있게 됩니다.

  1. 전역 지침·프로젝트 지침·스킬·커넥터/플러그인의 차이를 구분하고, 무엇을 어디에 심을지 판단할 수 있다.
  2. 메타 프롬프팅으로 컨텍스트를 정리해, 완성도 높은 프롬프트를 스스로 만들 수 있다.
  3. Claude Code에서 권한 모드를 이해하고, 위험한 파일을 훅으로 직접 보호할 수 있다.
왜 이걸 배우는지 — 강사의 실무 사례

강사도 SM(시스템 운영) 업무에 Claude를 직접 쓰고 있습니다. 오늘 배우는 개인화·메타 프롬프팅·훅은 강사가 실제 유지보수 과제에 쓰는 하나의 흐름입니다. 블록 10에서 이 흐름 전체를 실제 화면으로 보여 드립니다.

5. 메타 프롬프팅 실습 38–63분 · 실습

실습

AI에게 작업을 바로 시키는 대신, 최적의 프롬프트를 먼저 함께 만들어 봅니다.

  1. 컨텍스트 그대로 던지기 (5분)새 대화를 열고, 각자의 실무 과제(또는 아래 예시)를 정리하지 않은 상태로 그대로 붙여 넣습니다. 
    법인카드 정산 과제에서 결재라인 자동 지정 로직을 개선하려고 한다.

- 기존 스크립트를 수정하는 작업
- 결재라인은 신청자 부서, 직급, 정산 금액 구간에 따라 달라짐
- 현재 로직은 예외 케이스(겸직자, 파견직 등) 처리가 빠져 있음
- 우선순위 규칙은 기존 상세설계서에 정리돼 있음
- 기존 스크립트의 네이밍·구조 컨벤션을 그대로 유지해야 함
- 변경 후에도 기존에 처리된 건의 결과는 달라지면 안 됨
  2. AI가 먼저 되묻게 하기 (5분) 
    지금까지의 내용을 기반으로 프롬프트를 만들려고 한다.
좋은 프롬프트를 만들기 위해 부족한 컨텍스트가 있다면 먼저 질문해줘.
    근사 목업 실제 질문 문구·개수는 실행마다 달라집니다.
    Claude — 응답 예시
    지금까지의 내용을 기반으로 프롬프트를 만들려고 한다. 좋은 프롬프트를 만들기 위해 부족한 컨텍스트가 있다면 먼저 질문해줘.
    • 결재라인 우선순위 규칙이 정리된 상세설계서는 어디서 확인할 수 있나요?
    • 겸직·파견직 외에 처리해야 할 예외 케이스가 더 있나요?
    • 이 로직이 구현된 파일·모듈 위치는 어디인가요?
    • 기존에 처리된 건과의 회귀 여부는 어떻게 검증할 계획인가요?
  3. 답변하며 성공 조건 명시 (5분)되묻는 질문에 아는 만큼 답하면서, "무엇이 되면 성공인지"도 함께 알려 주세요.
  4. 최종 프롬프트 요청 및 즉시 실행 (7분) 
    더 이상 필요한 정보가 없다고 판단되면 질문을 종료하고,
지금까지의 모든 답변을 반영하여 요구사항·영향 분석 프롬프트를 만들어줘.
규칙 명세, 예외 케이스 목록, 영향 범위를 포함해줘.

마지막으로 생성된 결과물을 검토하여 불필요한 내용을 제거하고 최적화해줘.

    완성된 프롬프트를 같은 대화에 이어서 바로 실행해 결과를 받으세요. 확인 기준: 규칙 명세·예외 케이스 목록·영향 범위 3가지가 모두 들어 있는지입니다.

  5. 결과물 점검 (3분)받은 결과에 누락된 요구사항이 없는지 확인하세요.

9. Hook 설정 실습 — 위험 파일 보호형 106–131분 · 실습

실습

.env 같은 민감 파일을 훅으로 확실히 차단해 봅니다.

  1. 훅 폴더 만들기 (2분) 
    mkdir -p .claude/hooks
  2. 차단 스크립트 작성 (8분)아래 내용을 .claude/hooks/block-env.sh로 저장하세요. 
    #!/bin/bash
FILE_PATH=$(jq -r '.tool_input.file_path // empty')

if echo "$FILE_PATH" | grep -qE '(^|/)\.env(\..*)?$'; then
  jq -n '{
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: ".env 파일은 훅으로 보호되어 있습니다. 직접 수정해 주세요."
    }
  }'
else
  exit 0
fi

    실행 권한을 부여하세요.

    chmod +x .claude/hooks/block-env.sh
  3. settings.json에 등록 (5분).claude/settings.local.json에 아래를 추가하세요. 
    {
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-env.sh"
          }
        ]
      }
    ]
  }
}
  4. 차단 동작 확인 (7분) 
    .env 파일에 TEST_KEY=123 한 줄을 추가해 줘.

    확인 기준: Claude가 파일을 수정하지 못하고, 보호 메시지를 응답에서 확인할 수 있습니다.

    근사 목업 응답 문구는 매번 다릅니다. 차단 메시지가 나타나는지로 확인하세요.
     Terminal — claude
    > .env 파일에 TEST_KEY=123 한 줄을 추가해 줘.

⛔ PreToolUse:Edit blocked
.env 파일은 훅으로 보호되어 있습니다. 직접 수정해 주세요.

죄송하지만 .env 파일은 훅에 의해 보호되어 있어 수정할 수 없습니다.
직접 파일을 열어 TEST_KEY=123을 추가해 주세요.
  5. 정상 파일은 통과하는지 확인 (3분)같은 방식으로 README.md에 한 줄 추가를 요청해 정상적으로 되는지 확인하세요.
체크포인트
  • .env 수정 요청이 훅에 의해 차단되는 것을 직접 확인했다.
  • README.md 수정은 정상적으로 진행되는 것을 확인했다.
