설명

이 모듈을 마치면 다음을 할 수 있습니다.

4. 핵심 개념

설명

4-1. 결론부터

같은 지시를 두 번 이상 붙여 넣었다면 스킬로 만들 때입니다. 공식 문서는 만들 시점을 이렇게 정의합니다 — 같은 지시·체크리스트·다단계 절차를 계속 대화에 붙여 넣게 될 때, 또는 CLAUDE.md의 한 절이 사실이 아니라 절차로 커졌을 때. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

4-2. CLAUDE.md와 스킬의 결정적 차이

CLAUDE.md스킬
언제 로드되는가매 세션 항상쓰일 때만 (설명만 상시 노출)
담기 좋은 것짧고 언제나 참인 사실여러 단계로 이뤄진 절차
길이 부담길수록 매 세션 비용 (200줄 기준)본문이 길어도 평소 비용이 거의 없음

CLAUDE.md와 달리 스킬의 본문은 쓰일 때만 로드되므로, 긴 참고 자료를 넣어도 필요해지기 전까지는 비용이 거의 들지 않습니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

한 번 로드되면 세션 내내 남습니다

스킬을 호출하면 그 본문이 대화에 한 번 들어가고 세션이 끝날 때까지 남습니다. 그래서 본문 자체는 간결해야 합니다. 왜·어떻게를 길게 서술하지 말고 무엇을 할지만 적으세요. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

4-3. 어디에 두는가

범위경로적용 대상
개인~/.claude/skills/<이름>/SKILL.md내 모든 프로젝트
프로젝트.claude/skills/<이름>/SKILL.md이 프로젝트만. 커밋하면 팀 전체

호출할 이름은 디렉터리 이름에서 나옵니다. .claude/skills/deploy-staging/SKILL.md는 /deploy-staging이 됩니다. 개인 스킬과 프로젝트 스킬의 이름이 겹치면 개인 것이 이깁니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

4-4. 커스텀 커맨드는 스킬로 통합됐습니다

기존 자료에서 .claude/commands/를 봤다면

커스텀 커맨드는 스킬로 통합됐습니다. .claude/commands/deploy.md 파일과 .claude/skills/deploy/SKILL.md 스킬은 똑같이 /deploy를 만들고 동일하게 동작합니다. 기존 .claude/commands/ 파일은 계속 동작하지만, 스킬은 지원 파일을 담을 디렉터리와 호출 제어 프론트매터를 추가로 제공합니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

둘 다 있고 이름이 같으면 스킬이 우선합니다. 이 커리큘럼은 새로 만들 때 스킬 형식만 씁니다.

4-5. 프론트매터에서 초급 범위로 쓸 3가지

모든 프론트매터 항목은 선택 사항이고, description만 권장됩니다. Claude가 언제 이 스킬을 쓸지 판단하는 근거이기 때문입니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

키무엇을 정하는가이 모듈에서
description무엇을 하고 언제 쓰는지. Claude의 자동 호출 판단 근거사용
disable-model-invocationtrue면 나만 호출 가능. Claude는 스스로 못 씀사용
user-invocablefalse면 Claude만 호출 가능. / 메뉴에서 숨겨짐개념만
부수 효과가 있는 작업엔 disable-model-invocation: true

공식 문서의 예시가 명확합니다 — "코드가 준비된 것처럼 보인다고 Claude가 배포를 결정하게 두고 싶지는 않습니다." 배포·커밋·메시지 전송처럼 되돌리기 어렵거나 외부에 영향을 주는 작업은 내가 직접 부를 때만 돌게 하세요. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

4-6. 실행 결과를 미리 넣는 방법

!와 백틱으로 감싼 명령은 스킬 본문이 Claude에게 전달되기 전에 먼저 실행되고, 그 출력이 그 자리를 대체합니다. Claude는 명령이 아니라 실제 데이터를 받습니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

실패하면 스킬 전체가 취소됩니다

주입 명령이 실패하면 해당 자리만이 아니라 스킬 호출 전체가 중단되고, Claude는 그 호출의 본문을 아예 보지 못합니다. 기본 bash에서는 0이 아닌 종료 코드가 대부분 실패로 취급됩니다(단, grep·git diff 등 일부 검색·비교 명령의 종료 코드 1은 예외적으로 정상 결과로 처리됩니다). 문제를 찾으면 1로 끝나는 검사 스크립트처럼 0이 아닌 값으로 끝날 수 있는 명령에는 || true를 붙이세요. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

4-7. 주입 명령은 승인을 요청하지 못합니다

주입 명령이 허용 규칙에 없으면, 평소처럼 승인을 묻는 대신 그 자리에서 호출 전체를 취소합니다. 일반 Bash 도구 호출과 달리 ! 명령은 실행 전에 사람에게 물어볼 방법이 없기 때문입니다. 이미 있는 규칙과 정확히 맞지 않으면 — 평소라면 "실행할까요?"라고 물었을 규칙까지 포함해서 — 곧바로 취소됩니다. 이때 메시지는 위 실행 실패(Shell command failed for pattern "...")와는 다른 Shell command permission check failed for pattern "..."입니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

6번 절의 SKILL.md도 예외가 아닙니다

python3 app.py 실행은 중급 02에서 만든 허용 목록에 없습니다. 허용 규칙을 먼저 추가하지 않으면 이 모듈의 스킬은 첫 호출부터 취소됩니다. 5단계에서 이 규칙을 추가합니다. (CLI 실행 결과 직접 확인 — Claude Code v2.1.246, 2026-08-26)

5. 단계별 실습

실습

만들 결과물: /check-app으로 호출되는 프로젝트 스킬 1개 (커밋까지).

  1. CLAUDE.md에서 옮길 절차를 찾습니다

    초급 04에서 적은 규칙을 다시 봅니다.

    셸 명령
    cd ~/claude-code-sandbox
cat CLAUDE.md

    "변경 후에는 반드시 python3 app.py inventory.csv를 실행해 결과를 확인한다"는 사실이 아니라 절차입니다. 4-1의 신호에 정확히 해당하므로 이것을 스킬로 옮깁니다.

  2. 스킬 디렉터리를 만듭니다
    셸 명령
    mkdir -p .claude/skills/check-app

    디렉터리 이름 check-app이 그대로 호출 이름 /check-app이 됩니다(4-3).

  3. SKILL.md를 작성합니다

    6번 절의 SKILL.md 전문을 .claude/skills/check-app/SKILL.md에 저장합니다.

  4. 스킬이 인식되는지 확인합니다

    세션을 열고(이미 열려 있다면 그대로) 아래를 입력합니다. 목록에 check-app이 보여야 합니다.

    세션 커맨드
    /skills
    세션을 다시 시작하지 않아도 됩니다

    Claude Code는 스킬 디렉터리의 변경을 감시해 재시작 없이 현재 세션에 반영합니다. 다만 세션 시작 시점에 없던 최상위 스킬 디렉터리를 새로 만들었다면 재시작이 필요합니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

    [캡처 C-01]
    화면
    /skills 목록
    진입 경로
    SKILL.md 저장 후 세션에서 /skills
    캡처 범위
    목록에서 check-app이 보이는 범위
    강조 표시
    check-app 항목(빨간 테두리)
    캡션
    디렉터리 이름이 그대로 호출 이름이 된다. 재시작 없이 목록에 나타난다.
    근사 목업 실제 화면과 다를 수 있는 근사 목업입니다. /skills는 대화형 메뉴를 여는 명령이라, 이 클라우드 환경에서 claude -p "/skills"로 실행하면 /skills isn't available in this environment.라는 실제 응답만 돌아옵니다(2026-08-27 확인). 목록의 범위 표기(Project, 경로 .claude/skills/)는 공식 스킬 문서의 위치 표를 따랐습니다 (출처: code.claude.com/docs/en/skills, 2026-08-27 확인). 다만 check-app이 실제로 이 이름으로 호출 가능한 상태라는 것은 화면이 아니라 동작으로 직접 확인했습니다 — 같은 샌드박스에서 claude -p "/check-app"과 claude -p "/check-app 30"을 실제 실행했더니, 서로 다른 기준값(10과 30)에 따라 알림 품목 수가 2개→3개로 실제로 달라졌습니다. 즉 목록 화면은 근사지만, 디렉터리 이름이 그대로 호출 이름이 된다는 캡션의 핵심 내용은 실행으로 확인된 사실입니다.
     Terminal — claude
    > /skills
 ⋮
 Project (.claude/skills/)
 check-app   재고 알림 도구가 정상 동작하는지 확인하고 결과를 보고합니다…
 ⋮
  5. 주입 명령을 미리 승인합니다

    4-7에서 본 것처럼 ! 명령은 승인을 물어볼 수 없어, 허용 규칙에 없으면 그 자리에서 호출이 취소됩니다. 중급 02에서 만든 ~/.claude/settings.json을 열어 permissions.allow 배열에 아래 규칙 한 줄을 추가합니다.

    ~/.claude/settings.json — permissions.allow 배열에 추가할 항목
    "Bash(python3 app.py *)"

    중급 02와 같은 방식으로 저장 후 JSON 형식을 검증합니다.

    셸 명령 · 예상 출력
    $ python3 -m json.tool ~/.claude/settings.json > /dev/null && echo "JSON OK"
JSON OK
    이 규칙 없이 다음 단계를 실행하면

    /check-app이 Shell command permission check failed for pattern "..."로 즉시 취소되고, Claude는 실행 결과를 전혀 보지 못한 채 승인을 요청하는 안내만 남깁니다. 규칙을 추가한 뒤에도 안 되면 permissions.allow 배열의 쉼표와 따옴표가 정확한지 확인하세요.

  6. 직접 호출해 봅니다 (프롬프트 A)
    세션 입력
    /check-app

    스킬 본문의 ! 명령이 먼저 실행되어 실제 실행 결과가 이미 들어간 상태로 Claude가 답합니다. Claude가 app.py를 읽어 추측한 것이 아니라 진짜 출력을 본 것입니다.

    여기까지 — 스킬 동작
    • /skills 목록에 check-app이 있다
    • /check-app을 입력하면 실행 결과를 근거로 답한다
    • 응답에 실제 알림 문구([재고 부족] …)가 포함돼 있다

    스킬 호출이 Shell command failed for pattern "..."으로 중단되면 4-6의 실패 규칙에, Shell command permission check failed for pattern "..."로 중단되면 4-7과 앞 단계(허용 규칙 추가)에 걸린 것입니다. 7번 절을 확인하세요.

  7. 인자를 넘겨 호출합니다 (프롬프트 B)

    기준값을 바꿔 확인합니다. $ARGUMENTS가 입력한 값으로 치환됩니다.

    세션 입력
    /check-app 30

    초급 03에서 만든 명령줄 인자 기능이 여기서 쓰입니다. 기준값 30이면 3개 품목이 전부 나와야 합니다.

  8. CLAUDE.md에서 옮긴 절차를 지웁니다 (프롬프트 C)

    스킬로 옮겼으니 CLAUDE.md에는 스킬을 가리키는 한 줄만 남깁니다. 같은 내용이 두 곳에 있으면 나중에 어긋납니다.

    프롬프트
    CLAUDE.md의 "변경 후에는 반드시 python3 app.py inventory.csv를 실행해
결과를 확인한다" 줄을 지우고, 대신 아래 한 줄로 바꿔 주세요.

- 변경 후 동작 확인은 /check-app 스킬로 한다.
  9. 줄어든 CLAUDE.md를 확인합니다
    셸 명령
    cat CLAUDE.md
wc -l CLAUDE.md

    절차가 스킬로 빠지면서 CLAUDE.md가 짧아졌습니다. 이것이 4-2에서 말한 매 세션 비용을 줄이는 방법입니다.

  10. Claude가 스스로 부르는지 확인합니다

    슬래시 없이 자연어로 물어봅니다. description이 잘 쓰였으면 Claude가 스킬을 알아서 씁니다.

    프롬프트
    지금 재고 도구가 정상 동작하는지 확인해 주세요.

    스킬이 자동으로 불리지 않았다면 description에 사용자가 실제로 쓸 표현이 빠진 것입니다(7번 절).

    여기까지 — 두 가지 호출 방식
    • /check-app으로 직접 부를 수 있다
    • 자연어로 물어도 Claude가 알아서 부른다
    • CLAUDE.md에서 절차가 빠지고 스킬을 가리키는 한 줄만 남았다

    자동 호출이 안 되면 description을 고쳐 4단계부터 다시 확인하세요. 직접 호출만 되어도 실습은 계속할 수 있습니다.

  11. 커밋합니다

    프로젝트 스킬은 커밋해야 팀이 씁니다.

    셸 명령 · 예상 출력

6. 예제 코드·예제 프롬프트

실습 자료

예제 코드 — SKILL.md 전문

사전 준비물: .claude/skills/check-app/ 디렉터리, 초급 03에서 명령줄 인자를 지원하도록 고친 app.py.

.claude/skills/check-app/SKILL.md — 발췌가 아닌 전문입니다
---
description: 재고 알림 도구가 정상 동작하는지 확인하고 결과를 보고합니다. 변경 후 동작 확인, 재고 도구 점검, 알림이 제대로 나오는지 물을 때 사용합니다.
argument-hint: [기준값]
disable-model-invocation: false
---

## 기본 기준값으로 실행한 결과

!`cd "${CLAUDE_PROJECT_DIR}" && python3 app.py inventory.csv 2>&1 || true`

## 지정한 기준값으로 실행한 결과

!`cd "${CLAUDE_PROJECT_DIR}" && python3 app.py inventory.csv $ARGUMENTS 2>&1 || true`

## 할 일

위 두 실행 결과를 보고 아래를 보고하세요.

1. 기본 실행이 알림을 정상 출력했는지
2. 기준값을 바꿨을 때 결과가 달라졌는지
3. 오류 메시지가 있으면 원인과 확인할 파일

출력 문구의 형식(`[재고 부족] 품목명 - 현재 N개`)이 깨졌다면 반드시 지적하세요.
다른 시스템이 이 형식을 파싱합니다.

각 부분을 이렇게 쓴 이유:

부분이유
description에 "변경 후 동작 확인", "재고 도구 점검"Claude의 자동 호출 판단 근거입니다. 사용자가 실제로 쓸 표현을 넣어야 합니다
|| true4-6의 실패 규칙 때문입니다. 앱이 오류로 끝나도 스킬 호출이 통째로 취소되지 않게 합니다
2>&1오류 메시지도 Claude가 보게 합니다
${CLAUDE_PROJECT_DIR}세션의 작업 디렉터리가 어디든 프로젝트 루트에서 실행되게 합니다. 중괄호를 반드시 붙입니다 — 중괄호 없는 $CLAUDE_PROJECT_DIR는 권한 검사에서 "simple_expansion"으로 거부되어 호출 전체가 취소됩니다
argument-hint: [기준값]이 스킬이 인자를 받는다는 것과 그 의미를 자동완성에 보여주는 힌트입니다. 실행 결과에는 영향을 주지 않습니다
disable-model-invocation: false읽기만 하고 부수 효과가 없으므로 Claude가 알아서 불러도 안전합니다. 기본값이지만 의도를 드러내려고 명시했습니다

예상 출력: 파일 저장이라 출력이 없습니다.

성공 확인 방법: 세션에서 /skills를 실행해 목록에 check-app이 나타나면 성공입니다.

응답은 매번 다릅니다

프롬프트 A — 직접 호출

사전 준비물: SKILL.md가 저장되고 /skills 목록에 나타난 상태. ~/.claude/settings.json에 Bash(python3 app.py *) 허용 규칙이 추가된 상태(5단계) — 없으면 권한 검사 실패로 호출이 취소됩니다.

실행할 입력 전문

예상 출력(응답 예시): 기본 기준값 실행 결과를 근거로 정상 동작 여부를 보고합니다. 두 번째 주입 명령은 인자가 없어 기본값으로 실행되므로 첫 번째와 같은 결과가 나옵니다.

성공 확인 방법: 아래 2가지가 맞으면 성공입니다.

프롬프트 B — 인자를 넘겨 호출

사전 준비물: 프롬프트 A를 마친 세션.

실행할 입력 전문
/check-app 30

예상 출력(응답 예시): 두 실행 결과가 다르다는 점과, 기준값 30에서는 3개 품목이 모두 나온다는 점을 보고합니다.

성공 확인 방법: 두 번째 결과에 품목이 3개 나오고, Claude가 두 결과의 차이를 언급하면 성공입니다. 차이가 없다면 $ARGUMENTS 치환이 안 된 것이니 SKILL.md의 철자를 확인하세요.

프롬프트 C — CLAUDE.md 정리

사전 준비물: 스킬이 동작하는 것을 확인한 상태, Manual 모드.

7. 트러블슈팅

설명
증상원인해결
/skills 목록에 안 나온다 경로가 틀렸거나, 세션 시작 후 최상위 스킬 디렉터리를 새로 만듦 경로는 .claude/skills/<이름>/SKILL.md입니다. 파일명은 대문자 SKILL.md여야 합니다. 그래도 안 보이면 세션을 재시작하세요.
Shell command failed for pattern "..."로 중단된다 주입 명령이 0이 아닌 코드로 끝남 4-6에 따라 명령 끝에 || true를 붙입니다. 오류 메시지는 [stderr] 아래에 표시되니 함께 읽으세요.
Shell command permission check failed for pattern "..."로 중단된다 주입 명령이 허용 규칙에 없어 승인을 묻지도 못하고 취소됨(4-7) 중급 02의 방식으로 ~/.claude/settings.json의 permissions.allow에 실행하려는 명령과 정확히 맞는 규칙을 추가합니다(5단계). ${CLAUDE_PROJECT_DIR}처럼 중괄호 있는 치환을 썼는지도 확인하세요 — 중괄호 없는 $VAR 형태는 이 검사에서 항상 거부됩니다.
스킬이 자동으로 안 불린다 description에 사용자가 쓸 표현이 없음 공식 트러블슈팅 순서를 따릅니다. ① 사용자가 자연스럽게 말할 키워드가 description에 있는지 ② 어떤 스킬을 쓸 수 있나요?로 인식 여부 확인 ③ 요청을 설명에 가깝게 바꿔 보기 ④ /스킬명으로 직접 호출. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)
프론트매터를 고쳤는데 반영이 안 된다 YAML이 잘못되면 메타데이터가 빈 채로 로드됨 --- 구분자와 들여쓰기를 확인합니다. YAML이 깨지면 /스킬명 호출은 되지만 description이 없어 자동 호출이 안 됩니다. --debug로 파싱 오류를 볼 수 있습니다. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)
스킬이 첫 응답 뒤로는 영향을 안 주는 것 같다 내용은 남아 있으나 모델이 다른 방법을 택함 내용은 보통 그대로 있습니다. description과 지시를 더 분명히 쓰거나, 세션이 길어져 압축됐다면 스킬을 다시 호출해 본문을 되살리세요. (출처: code.claude.com/docs/en/skills, 2026-08-26 확인)

7-2. 흔한 잘못된 습관

습관겉으로 나타나는 모습대응
스킬 본문에 배경 설명을 길게 쓴다 잘 동작하지만 호출할 때마다 컨텍스트를 크게 차지하고 세션 내내 남음 무엇을 할지만 적고 왜·어떻게는 뺍니다. 긴 참고 자료는 별도 파일로 분리해 SKILL.md에서 가리킵니다.
CLAUDE.md와 스킬에 같은 내용을 둔다 당장은 문제없지만 한쪽만 고쳐져 나중에 서로 어긋남 절차는 스킬에만 두고 CLAUDE.md에는 가리키는 한 줄만 남깁니다(8단계).
부수 효과가 있는 스킬을 자동 호출로 열어 둔다 평소엔 편한데, 어느 날 Claude가 알아서 배포·커밋을 실행함 배포·커밋·전송 계열에는 disable-model-invocation: true를 붙입니다(4-5).
동작을 확인하지 않고 커밋한다 내 화면에서는 되는데 팀원 환경에서 주입 명령이 실패 커밋 전에 /스킬명과 자연어 호출을 둘 다 시험합니다(6·10단계).
